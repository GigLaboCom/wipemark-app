# UI icons

The in-window glyph set. Not to be confused with the sibling
`../icon/` directory, which holds the **application** icon in the
rasterisations a bundler reads — those are read from disk by
`cargo-bundle`, these are baked into the binary and painted by the app.

Every file here becomes an `IconName` variant. `arrow-right.svg` →
`IconName::ArrowRight`, resolved at render time as the asset path
`icons/arrow-right.svg`. The enum is generated by
`apps/wipemark-app/build.rs`; there is nothing to update by hand.

## Rules a file here must satisfy

- **Kebab-case filename**, `^[a-z][a-z0-9-]*\.svg$`, matching the
  FontAwesome source filename so an icon can be traced back to the
  corpus. The build script fails on anything else.
- **`fill="currentColor"`.** `Icon::color(...)` is `text_color`
  underneath, and GPUI only substitutes that for `currentColor`. A
  hardcoded `fill="#4a90d9"` renders the same in both themes and
  ignores every `.color()` call, silently. Enforced by
  `every_icon_paints_with_current_color`.
- **Self-contained.** No `<image>`, no external `xlink:href`, no font
  references. The bytes are embedded verbatim; nothing resolves a
  second file at paint time.

## Source and attribution

Every SVG in this directory comes from **Font Awesome Free 7.2.0,
Solid** style, unmodified, with the FA attribution comment left inline
as authored — the icons are CC BY 4.0, and that comment is the
attribution. See the repository-root `NOTICE` for the license terms.
`every_icon_is_a_free_glyph` refuses a file whose comment says
anything else: Pro Solid is the same artwork under a different
licence, and the comment is the only thing in the file that tells the
two apart.

Two filenames depart from the corpus. `close.svg` carries the content
of FA `xmark.svg`: `IconName::Close` is the affordance *dismiss this
UI* and `IconName::Xmark` is the action *reject this change*; they
render identically today, and separating them now means the day they
diverge is a one-file edit rather than a call-site audit. `eye-off.svg`
is FA's `eye-slash.svg` under the name `gpui_component` asks for, and
`case-sensitive.svg` and `replace.svg` — FA's `font.svg` and
`arrow-right-arrow-left.svg` — are the same arrangement for the two
toggles of the editor's search panel.

## Adding one

```sh
scripts/promote-icon.sh broom     # -> broom.svg, IconName::Broom
```

The set is deliberately small — fifty-six glyphs, each mapped to a
surface that E6–E9 actually builds. Promote a new one when a surface
needs it, not in anticipation. The script finds the corpus (a pulled
`dev-staging/`, a `--from` path, `$WIPEMARK_FA_CORPUS`, or another
checkout on this machine — the package is public, so the pull needs no
token) and checks the rules above, and the Free attribution, before
the file lands. `docs/architecture/icons.md` has the whole workflow, and
the note on handing one of these to a `gpui-component` control.
