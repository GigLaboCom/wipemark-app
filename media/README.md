# media — the tools that make Wipemark's screenshots, clips, video and site images

Everything a person sees *about* Wipemark outside the application — the
README's pictures, the website's gallery and icons, the intro video — is
generated by the tools in this directory. The tools are committed; **what they
make is not**: every output goes to `media/out/`, which is gitignored, and is
made again whenever it is needed (the owner, 2026-10-16: "keep the generation
apart, in a subfolder, without the assets themselves; they can be
regenerated").

| directory | makes | into |
|---|---|---|
| [`screenshots/`](screenshots/README.md) | the stills and the short clips, from a release build run on a demo folder, captured window by window | `media/out/screenshots/`, `media/out/clips/` |
| `video/` | the intro video, its poster, a short loop and its captions, composed from the clips and stills | `media/out/video/` |
| `site-images/` | the website's favicon, touch icon, header logo, glyph sprite and Open Graph picture, from the application's own icon and glyphs | `media/out/site/` |

`scripts/site/build.sh` puts the website's pages (`site/`) and these outputs
together in `site/dist/`.

**The one exception: the README's screenshots** (the owner, 2026-10-18: "add
the main screenshots too"). Eight stills from `media/out/screenshots/` are
committed in `docs/screenshots/`, so the README shows them on GitHub, and
the README names its pictures there. The main window, its dark twin and
Compare are scaled to 1600 pixels (ffmpeg, lanczos), twice the README's
column, and the before-and-after picture to a 1600-pixel JPEG; the others are
as taken, already smaller. `compare-dark.png` is left out. A still taken again is
copied over its namesake in the same way, never added beside it.

## Where the outputs will be kept — open

Until the owner decides, the other outputs exist only where they were
generated, so the video and the website are built and deployed from that
machine. The choices:

- **Cloudflare R2 behind a `giglabo.com` subdomain**, as lazy-shot keeps its
  media: one place for the site, the README (by absolute URL) and the video,
  no per-file limit that matters, nothing in git.
- **A GitHub release used as a shelf** (for example a `media` release whose
  files are replaced): free and next to the code; the URLs name the release.
- **A repository of its own** for the outputs, so this one stays light.

Whichever it is, the build and the README then name that place, and the Pages
workflow can fetch from it.

## Rules every tool here keeps

- **Only Wipemark's own windows.** A still is one window, captured by its id
  (`screencapture -o -l`); a clip records one window through ScreenCaptureKit
  (`screenshots/sckrec.swift`). Never a region of the screen: whatever else is
  on it would end up in the frame.
- **Nobody's profile.** The demo lives in `/Users/Shared/Wipemark Demo/` with a
  scratch data directory there; no image may show a user name, a home folder,
  an e-mail address, a host name or a terminal's title bar. The command line
  is never captured from a terminal window: `screenshots/cli-render.py` draws
  the text a real run printed.
- **The owner's pictures and texts only.** The Gemini and Grok pictures are
  the owner's own (`fixtures/image/`); the texts are written for the demo.
- **Nothing on the owner's screen that is not needed.** A run is short, starts
  its own instance on the demo data, and quits it by its own pid.
