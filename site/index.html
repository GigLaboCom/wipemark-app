Take the AI marks out of your own text and pictures.

AI tools can leave marks in what you make with them without asking you: invisible characters in text, provenance metadata and visible logos in pictures. Wipemark finds them, removes what it can prove is there, and tells you exactly what it did. It runs on your machine.

The intro

What it removes

Three kinds of marks, each removed only once it is shown to be there

Wipemark looks before it changes anything, and every change it makes is listed. What it cannot settle, it says it cannot settle.

Invisible characters in text

  • Deterministic
  • No model
  • Offline

Zero-width characters, bidirectional controls, tag characters, variation selectors, soft hyphens, private-use and noncharacter code points — recognised by the properties Unicode 18.0 gives every character. The same text gives the same result on every machine, and every finding has a position you can check.

Characters that belong to the text stay: the joiner inside an emoji, the non-joiner inside a Persian word. A look-alike letter from another alphabet, such as a Cyrillic “а” in an English word, is reported and kept; the command line replaces it only when asked.

Provenance metadata in pictures

  • PNG
  • JPEG
  • WebP

C2PA manifests; XMP and IPTC fields that declare a picture made by a model; generation parameters and the generator signatures that tools such as Stable Diffusion WebUI, ComfyUI, InvokeAI, NovelAI, Midjourney, OpenAI, Adobe Firefly, Google and Microsoft write into a file.

The file is cut into its blocks and only the provenance blocks are dropped: the pixels are not re-encoded. Camera data, orientation and the colour profile stay.

Visible marks

  • Gemini
  • Grok on X

Gemini’s sparkle, in its earlier and its current form, and Grok’s wordmark, white or black, on pictures saved from X. A mark comes off only after Wipemark has proved it is there. A mark over solid, opaque content is reported and left alone.

Taking a mark off means writing the picture again: a JPEG is saved at quality 95, a lossy WebP as lossless.

Optional: rewrite a text with a model

Some marks live in word choice rather than in characters, and no character filter reaches them. Wipemark can rewrite a text paragraph by paragraph with a model on your machine — llama.cpp, on Metal on a Mac and on Vulkan on Linux — or with an endpoint you choose: Ollama, or any OpenAI-compatible server.

A rewritten paragraph that fails a check is never used; the original paragraph is kept. A rewrite is best-effort and the report says so — read it in Compare before you use it.

Cleaning needs no model. Rewriting is never required.

How it works

Look first, change only what is proved, say what happened

  1. Hand it over

    Drop files, pictures or text on the main window or the panel, paste, or import. Everything lands in one list.

  2. It looks first

    Each row says what was found before anything is changed.

  3. Clean, or rewrite

    The result goes beside the original as name.cleaned.ext or name.rewritten.ext. Nothing is written over.

  4. Read the report

    It lists what was removed and where, and what could not be established.

Every report has three shelves

  • RemovedWhat was taken out, counted, with its position.
  • Done by a modelWhat a rewrite changed, when there was one.
  • Not establishedWhat no check here can settle — whether a vendor’s own detector still flags the result, whether a text was written by a person, and marks in schemes this version does not implement. This shelf is never empty.

Local by default

  • Cleaning text and pictures runs on your machine and never needs a network.
  • A rewrite runs on your machine with a model you downloaded, unless you choose an endpoint.
  • An endpoint on another machine is refused until you turn on Allow a remote endpoint in Settings › Engine. An API key is never sent over plain http to another machine.
  • Keys live in the system’s credential store — the Keychain on macOS, the Secret Service on Linux — never in a file.
  • Wipemark goes online only to download a model you pick, checked against its published hash, and to reach an endpoint you set up. There is no telemetry and no account.
  • Its list of documents keeps names, paths and what was done — never the text of a file. A pasted text is kept, with its rewrite, until you remove its row. Logs never contain a document.
Where you use it

Windows, a panel, a command line and an MCP server — one list

Whatever arrives — from the main window, the panel, the command line or an agent — joins the same list in the main window.

The main window

Drop, paste or import files and texts. Clean or rewrite one row, or all of them; a rewrite survives a restart and resumes where it stopped.

The panel

A small window for a quick drop, called up by a shortcut you can change: ⌘⌥D on a Mac, CtrlAltD elsewhere.

Compare

A text and its result side by side, with the differences marked. Edit the result there and save it.

Menu bar and tray

Show the window or the panel, unload a model, switch the appearance, open Settings or quit.

The command line

wipemark-cli with inspect, clean, audit, rewrite and models. Exit codes a script can act on: 0 clean, 1 findings, 2 refusal, 3 partial.

wipemark-cli inspect draft.md
wipemark-cli clean draft.md
wipemark-cli audit notes/ --sarif

The second line writes draft.cleaned.md beside the file; audit walks a folder and answers in text, JSON or SARIF.

MCP, for agents

Off by default. Turned on in Settings › MCP, it listens on 127.0.0.1:5056 and offers inspect, clean, rewrite, inspect_image and clean_image, so an agent can check its own output. Settings has a snippet for Claude Code, Claude Desktop or n8n.

Install

Open the .dmg and drag Wipemark onto Applications.

The first time you open it

This build is not notarized by Apple, so macOS blocks it the first time and says it could not verify Wipemark. To open it:

  1. Click Done (not Move to Trash).
  2. Open System Settings › Privacy & Security.
  3. Under Security, where it says Wipemark was blocked, click Open Anyway.
  4. Confirm with your password, then click Open.

You only do this once.

The command line on a Mac

wipemark-cli is inside the app. Link it into a folder on your PATH:

mkdir -p ~/.local/bin
ln -s /Applications/Wipemark.app/Contents/MacOS/wipemark-cli \
      ~/.local/bin/wipemark-cli

The tray icon and Wayland

The tray icon needs libayatana-appindicator3; on GNOME it also needs the AppIndicator extension, which Ubuntu has on by default. Without a tray, closing the main window quits Wipemark.

On a Wayland desktop the windows run through XWayland, so the panel opens where you place it. WIPEMARK_WAYLAND=1 runs them as native Wayland windows instead.

Windows is not in this version, and neither is Linux on ARM. There are no automatic updates: download the next version yourself.

Models for rewriting (optional)

Cleaning needs no model. To rewrite on your machine, the first launch looks at its memory and graphics and suggests one model from this catalogue, then downloads it. Every download is checked against its published hash, and an interrupted one resumes. A GGUF model you already have can be added instead.

Questions

Frequently asked

Is Wipemark free?

Yes. Version 0.1.0 is free to use: no account, no trial, no activation, nothing locked.

Its licence is the Functional Source License 1.1, with Apache 2.0 as the future licence (FSL-1.1-ALv2). In plain words: the source is public, and you may use, copy, change and share it for any purpose except offering it, or something built from it, as a commercial product or service that competes with it. Two years after each version is released, that version also becomes available under the Apache License 2.0. The licence text is what binds.

What is it for?

For removing marks that software put into your own files without asking: a hidden character carried over from a chat into your notes, a manifest a generator attached to a picture you made for your own page.

It is not a way to claim you wrote something you did not, and it does not try to be one: every report says that human authorship is not established by anything Wipemark checks.

Does it guarantee that a file is free of marks?

No. It removes what it can prove is there and says what it could not establish. Every report ends with that list: whether a vendor’s own detector still flags the result (not tested — there is nothing here to test it against), whether a text was written by a person (not established by any check), and marks in schemes this version does not implement (not searched for).

A rewrite is best-effort, and the report says what the model changed. Marks hidden inside a picture’s pixels, which no eye sees, are neither looked for nor removed.

Does it work offline?

Yes. Cleaning text and pictures never needs a network. Rewriting on your machine works offline once a model is downloaded. Wipemark goes online only to download a model you choose and to reach an endpoint you set up. It has no telemetry and no automatic updates.

Which files does it take?

Text: plain text, Markdown, HTML, XML, JSON, CSV and RTF, in UTF-8, UTF-16 or UTF-32, and text you paste or drop. Pictures: PNG, JPEG and WebP.

TIFF, HEIC and AVIF are recognised and refused in this version; Word documents, PDFs and other formats are not read. What a file is, Wipemark decides from its bytes, not from its name. Compare is for texts only.

Does it change my original file?

Not unless you ask it to. A result is written beside the original as name.cleaned.ext or name.rewritten.ext, or into a results folder you choose on the Retention page. If that name is taken, the windows add the row’s number (name.cleaned-12.ext) and the command line refuses. Nothing is written over.

You can choose to replace the file instead, on the Retention page or with wipemark-cli clean --in-place; the original is then kept beside it as name.original.ext. Only the command line’s --no-original keeps no copy.

Which models can it use?

The four open-weight models in its catalogue (see Models), any GGUF model you already have, or a server: Ollama, or any OpenAI-compatible endpoint. On your machine the model runs through llama.cpp — on Metal on a Mac, on Vulkan on Linux. Cleaning needs none of them.

What about Windows?

Not in this version. 0.1.0 is for Macs with Apple Silicon and for Linux on x86_64. There is no build for Intel Macs or for Linux on ARM yet, and none for glibc older than 2.39.

Where does it keep my data?

Everything Wipemark keeps is in one folder:

  • macOS: ~/Library/Application Support/com.GigLabo.wipemark
  • Linux: ~/.local/share/wipemark (or $XDG_DATA_HOME/wipemark)

It holds your settings; the list of documents — names, paths and what was done, never the text of a file (a pasted text stays until you remove its row); the downloaded models, which the Models page can move anywhere; and logs, which never contain a document. Results go beside the file they came from; a picture dragged out of a browser goes to your Downloads folder unless the Retention page names another. API keys are in the Keychain on macOS and the Secret Service on Linux.

How do I uninstall it?

Quit it from the menu bar or tray icon (Quit Wipemark), then remove the program: on a Mac, drag Wipemark.app to the Trash; on Linux, run sudo apt remove wipemark or delete the AppImage.

Removing the program leaves your data folder (with the models), your results and your keys alone. To remove them too: 

# macOS
rm -rf ~/Library/Application\ Support/com.GigLabo.wipemark
security delete-generic-password -s com.GigLabo.wipemark   # once per saved key

# Linux
rm -rf ~/.local/share/wipemark
secret-tool clear service com.GigLabo.wipemark

On GNOME, the panel’s shortcut is one of GNOME’s own: remove “Wipemark — panel” in Settings › Keyboard › Custom Shortcuts. The release notes on the download page list every file, including the AppImage’s menu entry and icons.
