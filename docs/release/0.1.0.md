# Wipemark 0.1.0

The first release. Wipemark removes AI provenance marks from **your own**
text and pictures, on your own machine. It is free to use; the licence is
FSL-1.1-ALv2 (`LICENSE.md`).

## What it does

- **Text, without a model.** It finds and removes invisible characters:
  zero-width characters, bidirectional controls, tag characters,
  variation selectors, private-use and noncharacter code points. Every
  finding is counted and has a position, so it can be checked. This
  always works offline.
- **Look-alike letters.** It reports a letter from another script inside
  a word, such as a Cyrillic "а" in an English word. By default it reports
  and keeps such a letter. Only `wipemark-cli clean --aggressive` replaces
  it.
- **Text, with a model.** It rewrites a text paragraph by paragraph to
  remove statistical marks. This is best-effort. The model runs on this
  machine: Metal on a Mac, Vulkan on Linux. You can use a server instead,
  such as Ollama or any OpenAI-compatible endpoint. A rewritten paragraph
  that fails a check is never used; the original paragraph is kept.
- **Pictures.** It removes AI provenance metadata (C2PA, EXIF, XMP, IPTC,
  generator parameters) from PNG, JPEG and WebP without touching the
  pixels. A camera's own data stays. It also removes the visible marks it
  can prove are there: Gemini's sparkle, and Grok's mark on pictures from
  X. When something stays, it says so.
- **It never changes your file.** A result goes beside the original as
  `name.cleaned.ext` or `name.rewritten.ext`. If that name is taken:
  - in the windows, the result gets the row's number, for example
    `name.cleaned-12.ext`;
  - the command line refuses.

  Nothing is written over.
- **It is honest about what it did.** Every report has three shelves:
  - what was removed, with positions;
  - what a model did;
  - what cannot be established.
  The third is never empty. Nothing here claims a text is
  "undetectable".

There are several ways to use it:

- **The main window.** Drop, paste or import files and texts into one
  list. Clean them, rewrite them, and compare a result with its original
  side by side. You can edit the result there and save it.
- **The panel.** A small window you call up with a shortcut: ⌘⌥D on a
  Mac, Ctrl+Alt+D elsewhere. Things you drop on it join the same list.
  It comes and goes on its own: a minimised or closed main window stays
  where it was.
- **The menu bar or tray icon.** Its items:
  - Show Wipemark;
  - Show the panel, or Hide the panel while it is up;
  - Unload model, while a model is loaded;
  - Appearance;
  - Settings…;
  - Quit Wipemark.
- **`wipemark-cli`.** The command line, with these commands:
  - `inspect`, `clean` and `audit <folder>`;
  - `rewrite`;
  - `models`.

  The exit codes are `0` clean, `1` findings, `2` usage or refusal and
  `3` partial. If the application is running, `rewrite` is done by the
  application.
- **An MCP server, for AI agents.** It is **off by default**. Turn it on
  in Settings › MCP. It listens on `127.0.0.1:5056` and offers `inspect`,
  `clean`, `rewrite`, `inspect_image` and `clean_image`. Settings › MCP
  has a snippet to paste into Claude Code, Claude Desktop or n8n.

**Nothing leaves your machine** unless you choose an endpoint on another
machine *and* turn on **Allow a remote endpoint** on the Engine page. An
API key is never sent over plain `http` to another machine. Keys live in
the system's credential store, never in a file. There is no telemetry.

## Install

### macOS (Apple Silicon)

`Wipemark-0.1.0-arm64.dmg` needs a Mac with Apple Silicon (M1 or later).
The app requires macOS 12 or later; this release was tested on macOS 26.
There is no build for Intel Macs.

1. Open the `.dmg` and drag **Wipemark** onto **Applications**.
2. Open Wipemark from Applications.

**The first time you open it.** This build is not signed with an Apple
Developer ID and is not notarized, so macOS blocks it the first time:
"Apple could not verify 'Wipemark' is free of malware". To open it:

1. Click **Done**. Do not choose Move to Trash.
2. Open **System Settings › Privacy & Security**.
3. Scroll to **Security**, where it says Wipemark was blocked, and click
   **Open Anyway**.
4. Confirm with your password, then click **Open**.

You only do this once. In a terminal, this does the same:

```sh
xattr -dr com.apple.quarantine /Applications/Wipemark.app
```

**The command line on a Mac.** `wipemark-cli` is inside the app. Link it
into a folder on your PATH:

```sh
mkdir -p ~/.local/bin                   # ~/.local/bin must be on your PATH
ln -s /Applications/Wipemark.app/Contents/MacOS/wipemark-cli ~/.local/bin/wipemark-cli
```

Through the link it still finds the graphics libraries inside the app, so
a rewrite on this Mac works with the application closed too.

### Linux (x86_64)

Wipemark needs glibc 2.39 or newer: Ubuntu 24.04, Debian 13, Fedora 40 or
newer. It also needs GTK 3 and a Vulkan driver. The command line needs
none of the desktop.

**AppImage**, `Wipemark-0.1.0-x86_64.AppImage`, carries everything it
needs except GTK and the graphics driver:

```sh
chmod +x Wipemark-0.1.0-x86_64.AppImage
./Wipemark-0.1.0-x86_64.AppImage                    # the application
./Wipemark-0.1.0-x86_64.AppImage --cli inspect x.md # the command line
ln -s "$PWD/Wipemark-0.1.0-x86_64.AppImage" ~/.local/bin/wipemark-cli
```

On its first run the AppImage adds itself to your applications menu. It
writes `~/.local/share/applications/wipemark.desktop` and its icons under
`~/.local/share/icons/hicolor/`. If your system has no FUSE, run it with
`--appimage-extract-and-run`.

**.deb**, `wipemark_0.1.0_amd64.deb`, for Ubuntu and Debian:

```sh
sudo apt install ./wipemark_0.1.0_amd64.deb
```

apt installs what it depends on: `libgtk-3-0t64`, `libvulkan1`,
`libgomp1`, `libxkbcommon-x11-0` and `libayatana-appindicator3-1`, among
others. It recommends a Vulkan driver (`mesa-vulkan-drivers`). The
programs go to `/usr/lib/wipemark/`, with `wipemark` and `wipemark-cli`
in `/usr/bin/`.

**On a Wayland desktop** the windows run through XWayland, so the panel
opens where you put it on the Placement page. Set `WIPEMARK_WAYLAND=1` to
run as a native Wayland window instead; the desktop then decides where
windows open.

**The tray icon** needs `libayatana-appindicator3`. On GNOME it also
needs the AppIndicator extension, which Ubuntu has on by default. Without
a tray, closing the main window quits Wipemark.

Not in this version.

## The first launch

A short walk-through opens over the main window:

1. it looks at this machine's memory and graphics;
2. you choose who rewrites (this machine or a server you name);
3. you choose a model or an endpoint.

You can skip it. To run it again, use Settings › General.

For rewriting on this machine it recommends one model from its catalogue
and downloads it. Every download is checked against its published hash,
and an interrupted one resumes. The catalogue:

| model | download |
|---|---|
| Qwen3 4B Instruct 2507 | 2.6 GB |
| Gemma 4 12B Instruct (QAT) | 6.7 GB |
| Gemma 3 12B Instruct (QAT) | 7.4 GB |
| Qwen3.8 27B | 12 GB |

A GGUF model you already have can be added on the Models page instead of
downloading one. Cleaning needs no model at all.

## Where your data lives

Everything Wipemark keeps is in one folder:

| | folder |
|---|---|
| macOS | `~/Library/Application Support/com.GigLabo.wipemark` |
| Linux | `~/.local/share/wipemark` (or `$XDG_DATA_HOME/wipemark`) |

What is in it:

- **`wipemark.db`**, with `wipemark.db-wal` and `wipemark.db-shm` beside
  it while Wipemark runs. It holds:
  - your settings;
  - the list of documents: names, paths and what was done, never the text
    of a file;
  - the rewrite queue, so a rewrite survives a restart. A pasted text with
    no file behind it stays here, with its rewrite, until its row is
    removed from the list.
- **`models/`**: the downloaded models. To move them anywhere, use the
  Models page.
- **`records/`**: what a check of a model file found.
- **`logs/`**: diagnostics. Never the text of a document.
- **`kept/`**: copies of pasted texts and their results, only if the
  Retention page asks for them.
- **`mcp.json`** and **`wipemark.sock`**: present only while Wipemark is
  running.

`WIPEMARK_DATA_DIR=/some/folder` moves all of it, for the application and
for the command line.

Results are not in this folder:

- A result goes beside the file it came from.
- A result with no file behind it, such as a picture dragged out of a
  browser, goes to your Downloads folder unless the Retention page names
  another.

**API keys** for an endpoint are in the system's credential store, under
the service name `com.GigLabo.wipemark`, one entry per server:
- on macOS, the Keychain;
- on Linux, the Secret Service, which is GNOME Keyring or KWallet.

## Uninstall

Removing Wipemark leaves the following alone:
- your data folder, including the models;
- your results;
- your keys.

Delete them yourself if you want them gone.

### macOS

1. Quit Wipemark: menu bar icon › **Quit Wipemark**.
2. Drag `/Applications/Wipemark.app` to the Trash.
3. To remove everything else:

   ```sh
   rm -rf ~/Library/Application\ Support/com.GigLabo.wipemark   # data, models, logs
   rm -f  ~/Library/Preferences/com.GigLabo.wipemark.plist       # written by macOS
   rm -rf "$(getconf DARWIN_USER_CACHE_DIR)com.GigLabo.wipemark" # Metal's shader cache
   rm -f  ~/.local/bin/wipemark-cli                               # if you made it
   security delete-generic-password -s com.GigLabo.wipemark       # one key; repeat until "could not be found"
   ```

   If you moved the models folder on the Models page, the models are where
   you moved them.

### Linux

1. Quit Wipemark: tray icon › **Quit Wipemark**.
2. Remove the program:
   - **.deb:** run `sudo apt remove wipemark`.
   - **AppImage:** delete the file, then its menu entry and icons:

     ```sh
     rm -f ~/.local/share/applications/wipemark.desktop \
           ~/.local/share/icons/hicolor/{32x32,128x128,512x512}/apps/wipemark.png
     ```

3. To remove everything else:

   ```sh
   rm -rf ~/.local/share/wipemark                       # data, models, logs
   secret-tool clear service com.GigLabo.wipemark       # endpoint keys, if any
   ```

4. **On GNOME**, the panel's shortcut is one of GNOME's own keyboard
   shortcuts. It stays after Wipemark is removed and then starts nothing.
   Remove it in **Settings › Keyboard › Custom Shortcuts**. It is named
   "Wipemark — panel", or "Wipemark — bring forward" for the second
   shortcut, in the language Wipemark was set to.

## Known limitations

**Platforms**
- **Builds.** There is no Windows build, no Intel Mac build and no Linux
  build for ARM. There is no Flatpak and no build for glibc older than
  2.39.
- **Updates.** There are no automatic updates: download the next version
  yourself.

**Shortcuts and windows**
- **Ubuntu.** The panel's default shortcut, Ctrl+Alt+D, is already
  GNOME's "Hide all normal windows". Wipemark says so; choose another in
  Settings › General.
- **Wayland outside GNOME.** There is no system-wide shortcut.
- **Native Wayland** (`WIPEMARK_WAYLAND=1`):
  - the desktop decides where windows open;
  - a Settings window may flicker when it is brought forward.
- **Mac, first launch of a new copy.** The model can take about half a
  minute to get ready. Meanwhile the status bar says "no engine
  configured" and Rewrite is greyed. It is quick after that.
- **Compare.** At its default width, the window can cut off the "Back to
  the rewrite" button at its right edge. Widen the window to see it.
- **Rows from the command line or an agent.** They show no file format in
  the list.
- **The Engine page, with an endpoint.** The Check appears only after you
  choose a Provider. If the page says "not configured", it does not say
  which field is missing: check Provider, address and model.

**Rewriting**
- **Best-effort.** A rewrite can let a broken or cut-off word through.
  This was seen with Qwen3.8 27B on a Russian text. Read a rewrite in
  Compare before you use it.
- **The voice profile.** It is shipped and can be chosen on the Rewriting
  page, but it is not the default.
- **8 GB graphics cards.** The larger models do not fit; Qwen3 4B does.
- **Waiting for a result.** A rewrite shows when it is finished; you do not
  see it being written.

**Pictures**
- **Visible marks.** Only Gemini's and Grok's on X are removed. A mark over
  solid, opaque content is reported, not painted over.
- **Grok marks.** At sizes not seen yet, a Grok mark may not be found. A
  faint Grok mark on a resized picture is sometimes missed: 15 times in
  720 tests.
- **Compare.** It is for texts only, not pictures.
- **Formats.** TIFF, HEIC and AVIF are not read yet.

**Models**
- **Old models.** A model you no longer use stays on disk until you remove
  it on the Models page.
- **Downloads.** There is no download mirror.
