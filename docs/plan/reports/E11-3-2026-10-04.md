## What was built

1. **An unknown critical PNG chunk** — `tests/gaps.rs`,
   `an_unknown_critical_chunk_is_structure`: `CgBI` and `ABCD` after
   `IHDR` are never listed and survive `AllMetadata`; the same name in
   lower case (`aBCD`) is metadata and goes. No code change.
2. **A C2PA manifest across APP11 segments** — `support::app11_split`
   builds one JUMBF box in two segments of one box instance, the second
   carrying only the repeated `LBox`/`jumb` header and filler (asserted:
   no `c2pa` in it). `a_c2pa_manifest_across_app11_segments_leaves_whole`
   (both C2PA, both removed, output = the bare JPEG) and
   `an_unlabelled_jumbf_of_another_instance_is_not_c2pa` (the grouping is
   by instance). No code change.
3. **The MP Index** — decided: **rewrite** (I1). `jpeg::mp_index` reads the
   first MPF header's MP Entry strictly (byte order `II`/`MM`, every offset
   inside the segment); `lib.rs`, `rebuild`, writes the first picture's
   Individual Image Size as the old value minus the bytes removed, in the
   index's byte order. Refused as `Unsupported::MultiPicture` when the index
   cannot be read or the size would underflow; an index with no MP Entry
   (E11-1's own fixture) is allowed as before. `support::app2_mpf_index`
   builds a real two-picture index; `the_mp_index_follows_a_removal_before_it`
   (both byte orders: the size is the new primary length, the second
   picture's size and offset unchanged and landing on its SOI, no other
   byte moved, the decoded raster identical) and
   `an_mp_index_that_cannot_be_read_refuses_a_removal`.
4. **Orientation as a reported fact** (I2, I3) — `src/exif.rs` reads IFD0's
   Orientation (bounded, both byte orders, with or without `Exif\0\0`);
   PNG `eXIf`, PNG raw `exif` profile (after the hex is decoded), JPEG
   APP1 and WebP `EXIF` blocks carry it; `StripReport::orientation_removed:
   Option<u16>` is the first removed block's value in 2–8. JSON:
   `"orientation_removed"` (number or `null`) after `kept`. The CLI says
   `cli-image-orientation-removed` when it is set, in either scope;
   `cli-image-exif-removed` and `cli-image-all-metadata` no longer claim a
   rotation for every EXIF block. MCP carries the field and no sentence.
   Tests: `a_removed_orientation_is_reported` (five containers/encodings,
   a camera EXIF kept by default and reported under `AllMetadata`),
   `orientation_one_is_not_a_rotation` (1, 0, 9), `exif::tests` (3),
   `json::tests::the_json_form_of_a_strip_report_is_exact`, CLI
   `the_rotation_is_said_only_when_it_was_removed`.
5. **Wording**: `cli-image-multi-picture` (en/ru/de) and the MCP refusal
   now say "would leave their index wrong" — true of both refusals.
   `docs/architecture/images.md` (what the crate computes, MPF, Orientation,
   the JSON keys, the CLI sentence) and `docs/architecture/cli.md`.

## Decisions (I-numbers; the series report maps them from D170)

| I | in one line |
|---|---|
| I1 | the MP Index's first-picture size is rewritten (old − removed), never left stale; unreadable or underflowing → `MultiPicture`; no MP Entry → nothing to do |
| I2 | `StripReport::orientation_removed`, IFD0 Orientation 2–8 of the first removed EXIF block; JSON key before the third shelf |
| I3 | the CLI says the rotation as a fact (new key); the two old sentences stop guessing |
| I4 | Apple's real `CgBI` (before `IHDR`) stays refused as `HeaderNotFirst` |
| I5 | only the **first** `MPF` header counts (it held the last before) — the index lives in the first picture's segment, and its offsets are relative to it; a removal between two MPF headers is now refused, as it should have been |
