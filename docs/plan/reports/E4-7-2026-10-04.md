**The document and `CLAUDE.md`.** No disagreement. One reading of the
task had to be chosen (I6, below): "unknown is never a mismatch" is read
as *a chunk whose language is unknown is never checked* — an **answer**
read as unknown is a mismatch, because every one of the bench's 32
obeying answers that passed was read as unknown (French), and a check that
let unknown through would have caught none of them.

## What was built (D95's four items)

1. **Selection and thresholds** (`select.rs`). The winner is the **most**
   diverged candidate that passed (tie → the earlier attempt); the no-op
   floor is **0.2**; D71's 0.15 penalty and its 0.5–2.0 window are gone
   (`Scores::score` is the divergence, maximised). Two length windows,
   `LengthWindows { long: 0.6–1.6, short: 0.5–2.0 }`, chosen by the chunk's
   words outside its placeholders (`prose_words`, boundary
   `SHORT_CHUNK_WORDS = 20`); `Options::length` holds both. Stored options
   are version 2 (`length`, `length_short`); a version 1 row is read with
   its one window for both. D61's 1 × 2 / 2 × 2 and "moderate" unchanged.
2. **The language check** (`job/attempt.rs`). `Rejection::Language {
   expected, found }` (JSON `{"kind":"language","expected":"en","found":null}`):
   the chunk's language known, the answer 20+ words, detected as another
   language **or none**. Only the final answer, against the chunk's
   language — `back_translate`'s step 1 answers in the pivot on purpose and
   is not checked. Order: guards → language → restore → floor.
3. **A list item is a chunk of its own** (`prepare/`). Every Markdown
   piece is its own unit; the glue placeholders, `Layout::glue`, the
   per-segment prefixes and `RestoreError::OutOfOrder` are removed (no
   input could produce them). `ItemBroken` (no field now) refuses a list
   item's chunk that comes back with more line breaks than it went in with.
   An item's context is the usual rule — the previous chunk's last two
   sentences: the item before it, or the lead-in for the first.
4. **`NumbersGuard`** (`wipemark-core/src/guard.rs`): a canonical `⟦n⟧`
   is not a number on either side (by the placeholder guard's own
   definition, `placeholder_at`). **Decided: "1800" for "1,800" stays a
   loss** (and "12 000" for "12000"): a separator's meaning depends on a
   language the guard cannot know ("1,800" is 1.8 in German), equating them
   would let 1.8 become 1800, and the contract asks for the same
   separators since D94. Pinned by `a_number_with_its_separators_changed_is_lost`.

Around them: `job::verdict` — the verdict after Layer A — is public and
is what the loop **and the bench** call (the bench's copy of the verdict
is gone, so its numbers are the loop's by construction). `select::RULES`
(selection, floor, the two 20-word thresholds) is hashed into the queue's
fingerprint, whose tag is now `wipemark-resume/2`: a job decided under
E4-3's rules is never resumed under E4-7's, and a later change of any rule
forgets every record without anyone bumping a tag. The report is version 2
(`passed.score` maximised, `item-broken` without `item`, `out-of-order`
gone; `language` rejections and `best_effort.selection: {"pick":
"most-diverged", "no_op_floor": 0.2}` added). No surface renders a single
rejection today (CLI and MCP report totals; the JSON is a format), so the
new rejection needs no catalogue sentence yet; E4-6b must word it when it
shows rejections (`Rejection` is exhaustive, so its build will say so).

Decisions I1–I17 are in the plan document §4; proposed D-numbers below.

## Open questions for the owner (product terms)

1. **Very short list items.** A list item of one to four words ("Python",
   "Rust", "Run it once") is now asked on its own, and a model mostly gives
   it back unchanged or blows it up into sentences — either way it stays
   as it was, which is honest, but every such item makes the command line
   report the run as **partial** (exit 3: "not every part was rewritten").
   Should items (and lines) under a few words be left alone *by design* —
   not asked, and not counted as "kept" — or is "partial" the right thing
   to say about them?
2. **More calls for lists.** A list of ten items is ten requests where it
   was one: +5 % on this corpus, more for list-heavy documents, and it
   weighs most on a computer without a graphics card. The price shown
   before a run already counts it. Acceptable?
3. **The language check can refuse a good rewrite** when the detector
   cannot place the result (1 in 1 887 here — an old-fashioned Russian
   literary paragraph); that paragraph then stays as it was. Acceptable as
   the cost of never shipping a translation?
