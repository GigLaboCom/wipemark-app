## What was built, per sub-step, and how it is gated

**The gate is one cargo feature**, `blend-preview`, of `wipemark-pixels`,
forwarded by `wipemark-picture` as its own `blend-preview` (the shape of
`planar-preview`, documented in both `Cargo.toml`s). It changes exactly one
thing: whether the **catalogue reads** the three schema additions. Without
it:

* a `bias` is a field `BlendJson` does not have, so a row carrying one is
  refused as it always was — serde's "unknown field `bias`" (the field is
  `#[cfg(feature = "blend-preview")]`);
* a `logo_map` that is not `null` is refused by name, "a logo colour map is
  not in this version" (its type widened to any JSON value so that the
  refusal and its message are unchanged whatever it holds);
* `"model": "linear-light"` is refused by name, "the linear-light blend is
  not in this version";
* `Draft::to_json` refuses a linear-light calibration, as it did.

Everything else is compiled in every build and reached only through a
profile that carries one of the three — which only a `blend-preview`
catalogue can produce. Every shipped profile is `encoded`, no bias, no map,
and on that profile every changed function reduces to the arithmetic it had,
operation for operation: `Law::inverse` is `restore::unblend` itself after a
`debiased` that returns the stored value untouched when there is no bias;
`Law::forward` is `a·l + (1 − a)·o`; `Law::out_of_range` is the old gap
loop; a subtracted bias of `0.0` in the planes is the value to the bit; the
interval's `Channel::forward` adds nothing when its bias is zero. No shipped
profile, map or threshold changed; `manifests/marks.v1.json` is untouched.

The new code is `crates/wipemark-pixels/src/blend.rs`:

| piece | what it is |
|---|---|
| `LogoMap`, `WmlError`, `WML_MAGIC` (public) | the `.wml` asset: `WML1`, `u16 width`, `u16 height`, `u8 16`, then the R, G and B planes, `width × height` `u16` each, row-major, little-endian; `L = sample·255/65535` (8-bit levels, fraction kept, D242). `read`, `write`, `new` with the `.wma`'s refusals (magic, depth, zero dimension, size, range) |

| `template_logos` | a profile's `L(p)` brought to a template by the very geometry the α map is (`shape_with`): `α·L` and `α` resampled alike, one divided by the other — how `synth` draws a `PerPixel` logo; the one colour where the template has no opacity |

### R9a — a bias (D308)

* **Schema.** `blend.bias: [b_r, b_g, b_b]` in stored 8-bit levels, scaled
  to the layout as the logo is; absent or `null` is `None` — no bias, not a
  zero added. A channel non-finite or at ±255 or past is refused.
* **Inverse.** `O = (I − α·L − b)/(1 − α)` where `α > 0` (`Law::inverse`),
  in `restore` (the mark and the capture noise), the gain sweep, `outline`,
  `residual` (the search's refinement), and the interval's RGB channels.
* **Proof.** The out-of-range interval moves by `b`: the inverse takes `b`
  off before the old gap is measured, which is `[α·L + b, α·L + b + (1 −
  α)·max]`.
* **Planes (R6).** The bias's linear part in `(Y, Cb, Cr)` (`ycc_delta`,
  JFIF's matrix without its offset) is taken off Y per pixel and off each
  chroma block in the proof (`Model::out_of_range`), the inverse
  (`invert_with`) and the blend-back (`Inverse::blend_back`), and rides into
  R8's channels (`Channel.bias`). A block whose pixels are partly outside
  the mark takes the whole bias — the block-mean model's own approximation.
* **Not done: the value.** No `b` is written anywhere: it is R4 §4.3's
  measurement on `gemini-midtone` (`scripts/analytics/bias.py`), which does
  not exist. The bench takes it from a row file (below).

### R9b — a per-pixel logo colour (D313)

* **Schema.** `blend.logo_map: { "asset": "<file>.wml", "sha256": "…",
  "size": [w, h] }` — the triple an opacity map is named by; the asset is
  hashed against its pin before it is read (`AssetProblem::Hash`), its size
  checked (`AssetProblem::Size`), its bytes read as a `.wml`
  (`AssetProblem::Wml`), and it must be **the size of every opacity map its
  profile lists** (a refusal by name otherwise). The document's
  "`gemini-v1-96-regressed`, `fitted: true`" is exactly such a row: one map,
  fitted, so `exact` stays false by D245 with no new rule.
* **Inverse and proof** read `L(p)` per template pixel everywhere they read
  `L` (`Verified::logo_at`, `Grid::logo`), the capture noise included. **In
  the planes** `L(p)` goes through JFIF's matrix per pixel for Y and, for a
  chroma block, as its pixels' `α`-weighted mean, `Σα·L/Σα` (the stored
  block mean is `Σα·L/n + …`).
* **Not done: the map.** No `.wml`, no `L_reg`, no `gemini-v1-96-regressed`
  row: they are R4 §4.4's `map_regress` output on `gemini-midtone` without
  its held-out files. `scripts/bench/wml.py from-tsv` turns that output
  (`pixels.tsv`'s `L_r`, `L_g`, `L_b`; empty cells filled with the global
  logo) into the `.wml` and prints its sha256 and the `blend` object.

### R9c — linear light (D311)

* **Schema.** `"model": "linear-light"`.
* **Inverse.** `O = unlin((lin(I) − α·lin(L))/(1 − α))`, `I` less the bias
  first if there is one.
* **Proof.** In light: `O_lin` outside `[0, 1]`, times `1 − α`, against the
  allowance converted at the stored value by the curve's slope —
  `lin(I) − lin(I − δ)` below, `lin(I + δ) − lin(I)` above, `δ` the eight
  stored levels of D240.
* **Planes and interval.** A blend in light is not linear in a JPEG's code
  values, so a linear-light profile is proved in RGB on every route
  (`verify_with` filters the planar model out), restored in RGB
  (`restore_one`), not inverted in the planes (`planar::invert` returns
  `None`) and never refined inside the interval (`interval::setup` returns
  `None`, so the restoration stands as R0 made it).
* **The calibration.** `calibrate` already chooses `encoded` or
  `linear-light` on greys and is unchanged. `Draft::to_json` under the
  feature writes `"model": "linear-light"` when every size chose it (and
  `MixedModels` when they disagree); the row loads in that build
  (`the_grey_captures_choose_the_blend_model`).

## Decisions proposed (none taken)

* **D308 (proposed, R9a)** — A profile may carry a **`bias`** in stored
  8-bit levels, one per channel, added by the vendor where the mark is
  drawn; the inverse is `(I − α·L − b)/(1 − α)` and the out-of-range
  interval moves by `b`. Its value is R4 §3's measurement, with the script
  and the run named. Absent is no bias. *(The document's text, with "where
  the mark is drawn" made explicit — `synth`'s convention.)*
* **D313 (proposed, R9b; the number the coordinator gave)** — A profile may
  carry a **`logo_map`**: a `.wml` asset (`WML1`, three 16-bit planes,
  `L = s·255/65535`) named by file, sha256 and size like an opacity map,
  the size of every opacity map of its profile. The inverse, the proof and
  the outline read `L(p)` per pixel, brought to the template as `α·L` over
  `α`; in the planes through JFIF's matrix per pixel and `α`-weighted per
  chroma block. It is accepted only on the held-out check (D240's residual
  ≤ 1.5 levels on `gemini-midtone`'s held-out `sat-*` and `black`), and its
  row is a fitted profile of its own (`gemini-v1-96-regressed`), never
  exact (D245).
* **D311 (proposed, R9c)** — D152 (`encoded`) is revisited only on **three
  agreements** (the grey calibration chooses `linear-light`; R4's residual
  grows with `Ô` monotonically; R5's matrix shows the linear inverse winning
  on linear composites and losing on encoded ones). If taken: the inverse
  in light, the proof in light with the allowance converted by the curve's
  slope, and a linear-light profile proved and restored in RGB only — never
  in the planes, never refined inside the interval. The experiment's result
  is recorded either way.
* **The feature (for whoever closes R9)** — `blend-preview` is removed
  when the last of the three is decided, as `planar-preview` will be.

## Deviations from the document

* **Built before its condition**, all three — the owner's instruction.
  Nothing is opened; the document's "builds only what R4 says yes to" now
  governs **opening**, not building.
* **`logo_map` is an object**, `{asset, sha256, size}`, not a bare asset
  id: the pin needs a place, and the opacity maps' own triple is the
  catalogue's shape for it.
* **A logo colour map must be the size of every opacity map of its
  profile** — the simplest rule that keeps one `L(p)` meaning one thing;
  R9b's row has one map anyway.
* **Linear light never takes the planar or the interval path.** The
  document says the planar path and R8's methods use the new blend "where
  they use `α·L`"; for the bias and the map they do, for linear light they
  cannot (the planes and the DCT are linear in code values), so a
  linear-light profile stays in RGB, unrefined.
* **R9c's miniature matrix is measured by the mean and the largest error**,
  not "within a level": the sRGB curve amplifies the rounding of a linear
  composite under the mark's body (about ×3.4 at 80 → 190 levels), so a
  correct linear inverse is within a level on average and not everywhere.
* **`the_catalogue_still_refuses_what_was_not_built`** is written for this
  arrangement — the feature opens all three at once, so it checks "without
  it, each refused; with it, each read" rather than "with R9b only,
  `linear-light` still refused". Should one sub-step be taken and another
  closed, the closed one's code goes (above) and the test's other half
  says "refused" for it again.
* **The capture noise under a non-encoded law** is looked for with the
  profile's own inverse (`stored − inverse`) in place of the encoded lift;
  `measure_at` draws its stand-in with the profile's blend. Both are today's
  expressions on every shipped profile.
