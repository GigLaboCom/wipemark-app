## Deviations from the document, and why

1. **A `file:///` row in `identifiers_have_the_five_shapes`.** With only
   the document's rows, deleting the URL shape left the suite green:
   every URL with a scheme and a host is also a path (`https:` and the
   host are two non-empty segments), so `https://x.y` and
   `https://example.com/docs/setup` stay identifiers through the path
   shape. A URL with fewer than two non-empty segments — `file:///`,
   `https://` — is the only thing the URL shape alone sees. Under §0.4 a
   protection with no red test has to get one or go; the shape is A §6's,
   so it got the row. Worth knowing: the URL shape is almost redundant.
2. **One test the document does not name:**
   `the_faithful_pair_is_what_the_document_measured` asserts §5's
   measurements of `SOURCE`/`FAITHFUL` (239 and 258 code points, the
   placeholders, the six numbers, the five identifiers), so a later edit
   of the literals cannot quietly hollow out the tests built on them.
3. **Two more rows in the identifier table:** `user’s_file` (the
   apostrophe inside a token is not trimmed — §4.3's `user’s` example,
   made an identifier so the row says something) and `foo_bar\u{200B}baz`
   (U+200B is not whitespace and does not split a token).
4. **A doc-test on `default_guards`** under §4.9's doc comment, as the
   acceptance criteria's suggested evidence that the items are reachable
   from outside the crate. It also goes red when two entries are swapped.
5. **`#[rustfmt::skip]` on `TRIM`.** Nightly rustfmt folds the `// D43`
   label into the middle of a line; the skip keeps A §6's eighteen and
   D43's eight on labelled lines of their own. It is still one
   `const TRIM: [char; 26]` with `\u{…}` escapes for the non-ASCII ones.
6. **`placeholders` walks `match_indices('⟦')`** instead of a
   `char_indices` loop that skips past a matched `⟧`. A placeholder's
   body is ASCII digits and a `⟧`, so no `⟦` can lie inside one and both
   loops visit the same openers; the comment in the code says so.

Nothing in README §3.2–3.3 was renamed or re-signed; nothing in it was
found wrong. No conflict between the document and `CLAUDE.md`.
