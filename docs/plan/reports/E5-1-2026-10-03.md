## Deviations from the document, and why

1. **The in-place human report goes to stdout, not stderr.** §4.1 says
   "(stderr)". `run.rs`'s table — which §4.5 says to extend — is that
   stdout carries one product and the report moves to stderr *only* when
   stdout carries the text; in place, stdout carries no text, so the
   report is the product, as for `-o file`. One rule rather than an
   exception; flip it in `run.rs` if the owner wants the other.
2. **`Downloads::rehash` was added to `wipemark-models`** (outside the
   document's "Files touched"). `Downloads::verify` trusts the size:mtime
   stamp, and `hash_file` is private; the alternatives were `sha2` in the
   CLI (a new dependency, which §6.4 forbids) or deleting the stamp from
   the CLI by spelling its private file name. `rehash` shares `verify`'s
   body behind a `trust_stamp` flag and has its own test,
   `a_full_rehash_does_not_trust_the_stamp` (a byte swapped under the
   same size and mtime: `verify` passes, `rehash` fails) — which is also
   E3's gate "a byte swapped in a weight fails verify", now true of the
   CLI.
3. **`pull` runs `Downloads::fetch` on its own thread, not
   `Downloads::spawn`.** `spawn`'s `Event::Failed(Option<String>)`
   flattens the error to English; `fetch` keeps the typed `StoreError`,
   so a mismatch, no room and a cancel each get their own catalogue
   sentence. The thread reports over `std::sync::mpsc` (the CLI has no
   `flume`).
4. **`ctrlc` 3.5.2 is the one new dependency** (workspace and CLI). `std`
   cannot install a signal handler portably, and a hand-written one would
   be the CLI's only `unsafe`. Its dependencies (`nix 0.31.3`,
   `windows-sys`, `dispatch2`) were already in `Cargo.lock`, which grew by
   the one package (recorded once without `--locked`, every gate then
   with it). The first Ctrl-C cancels; a second exits at once with 2.
5. **Two refusals the document did not list:** `--in-place` on a
   **symbolic link** (renaming it aside would set aside the link and
   leave the file it points at unchanged — a success over a document not
   touched), and on standard input (implied by "requires a file path").
6. **There is no CLI size limit** for one file — `inspect` reads to the
   end — so "over the size limit → unreadable" (§4.2) has no case, and
   `audit` does not invent one. A file that is not text is refused on its
   first four kilobytes. Said in `cli.md`.
7. **Step 2's question, observed:** findings with no change *do* happen —
   a homoglyph kept without `--aggressive` — and exit **1** over a file
   that was not touched and had no original set aside. Tested
   (`in_place_touches_nothing_when_nothing_changed`, the `pay.md` case).
8. **Exit codes the document left open, chosen:** a failed in-place write
   is 2 as §4.1 says, while `-o`'s failed write stays 3 as before (the
   in-place file is as it was; that run refused). `models list` is 3 when
   the folder exists and cannot be read; `verify` is 3 when a file cannot
   be read ("not read is not verified"); `pull` is 2 for every failure,
   network included; `rm` is 2 when the removal fails.
9. **What `audit` counts as a finding:** a file is "with findings" when
   its report is `suspicious` — `inspect`'s exit rule, so soft hyphens
   alone do not fail a hook. SARIF has one result per **occurrence** (a
   region per character, which is what an annotation needs) of every row
   `clean` would act on plus rows kept at `probable` or above (the same
   rows that make `inspect` exit 1). A leading byte order mark is not
   counted as a column; lines end at LF, CR and CR LF. `$schema` is set;
   `informationUri` is not. `run.properties` carries the Unicode version
   and the third shelf's ids, so the SARIF log is not the one report
   without them.
10. **`only_rewrite_still_refuses` asserts "not implemented yet"**, the
    refusal's unchanged sentence, rather than "not in this version" (§5's
    shorthand): §4.4 keeps the sentence. It replaces
    `the_commands_that_are_not_here_yet_still_refuse_at_two` and also
    asserts that `models list`, `models verify`, `models rm` and `audit`
    no longer refuse.
11. **`models_list_names_every_catalogue_entry_and_its_state`** covers
    absent, partial, mismatch and an unknown file in the folder; *present*
    needs the 2.5 GB file and is covered by the live check.
12. **The live check's `.part`** was 2,400,000,000 bytes, so 146 MB
    remained (the document said "about 100"); the interrupted pull took
    71.8 MB of it first, so the resumed pull fetched 74.6 MB.

Tests added beyond §5: `models_read_the_folder_and_the_choice_the_app_saved`
