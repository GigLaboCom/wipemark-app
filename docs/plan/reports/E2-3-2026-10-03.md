Document: [`docs/plan/E2-3-the-endpoint.md`](../E2-3-the-endpoint.md).
Branch `feat/e0-e6-shell`, started from `238653f` (the commit that filed
the document). Linux x86_64, toolchain 1.94.1, nightly rustfmt;
`LIBRARY_PATH` at the scratch `libxkbcommon-x11.so` symlink for every build
of `wipemark-app`. The application was launched **once** (below) and

## Where the document and `CLAUDE.md` disagreed

**When the key is read.** §4.4 has `EngineHost` read the key on the
background executor and then build the engine, which — because the host
builds the engine when the duty lands — would read the credential store
at startup. `CLAUDE.md` ("A credential is never a row") says the lookup
happens when it is needed and *not at startup*, because a keychain read
blocks and can raise a permission dialog. `CLAUDE.md` wins: the slot holds
the endpoint and the vault (`Slot::Keyed`), and the **first Check or job**
reads the key on a thread of its own, hands it to `duty::engine_for` (pure,
as §4.4 asks) and keeps the engine it builds. A read that fails is a
refusal that is not kept, so the next check asks again
(`an_endpoints_key_is_read_when_first_asked_and_not_at_startup`). The live
run's log shows it: "an endpoint is on duty; its key is read when it is
first asked" at startup, "the endpoint's key was read and its engine
built" at the first Check. `CLAUDE.md`'s credential rule now says the host
keeps the same rule.

## What was built

1. **`crates/wipemark-engine/src/http/`** — always compiled, no feature.
   * `mod.rs`: `HttpProvider`, `Reasoning` (the app's five values, with
     `wire()`), `HttpConfig` (`key: Option<Secret>`), `HttpEngine`. One
     thread (`wipemark-http`) per request; the `async fn` awaits a `flume`
     channel together with the `CancellationToken` and forwards each piece
     to the sink itself, so nothing reaches the sink after `complete`
     returns. Cancel returns `Err(Cancelled)` at once; dropping the call
     drops a channel the thread watches (next chunk, a retry's wait, or the
     read timeout). `warmup` sends nothing, `unload` does nothing,
     `info()` is `{vendor, model_id, local: on_this_machine, ctx_len: None}`.
   * `wire.rs`: the agent (`max_redirects(0)`, `http_status_as_error(false)`,
     connect 10 s, no gzip, the platform's proxy/trust as the downloader
     has them); `checked` refuses a non-`http(s)` scheme or userinfo before
     a socket opens; retries only before the first byte (connect failure,
     DNS, TLS, 429, 502/503/504 — at most two, `Retry-After` up to 10 s,
     500 ms / 1 s otherwise); status → refusal as in §4.3; the read loop.
     The read timeout is per wait on the socket, through `IdleRead`, a
     connector that wraps ureq's transport (deviation 4).
     `Secret::expose` is called here and nowhere else outside the vault.
   * `openai.rs` / `ollama.rs`: the two bodies (D59) and one payload each.
   * `sse.rs`: `Lines` (bytes cut at `\n`, a line decoded only whole — the
     UTF-8-safe accumulator), the SSE and NDJSON framings, and `Assembled`,
     whose verdict refuses an empty body, a stream without its end marker
     and an ended stream with no text.
   * `fake_server.rs` (test only): a scripted HTTP/1.1 server on
     `127.0.0.1:0` — status, headers (with an `{origin}` placeholder for a
     `Location` pointing back at itself), chunked body with pauses, a late
     status line, "drop after N bytes"; records requests and counts
     connections. `tests.rs`: the §5 tests and the ignored live one.

   `KeyRejected { status }`, `NotFound { detail }`, `RateLimited
   { retry_after_s }`, `Refused { status, detail }`, `KeyUnreadable
   { reason }` and `NoKey` (deviation 2), each with an English `Display` for
   logs and a sentence in en/de/ru.
3. **`wipemark-engine` → `wipemark-secret`** (D57), in

   `Cargo.lock` moves by those three lines.
4. **`duty::engine_for(performer, local, key: Option<Secret>)`**: an
   endpoint becomes an `HttpEngine` (vendor from `Performer::info`, the
   timeout row in seconds, the reasoning row mapped); `ENDPOINT_NOT_YET`
   and `NotImplemented` for endpoints are gone.
5. **`EngineHost`**: `Wanted::Endpoint { remote, key_saves }` — every
   endpoint field and the profile, plus a count of keys saved or forgotten
   (`Preferences::key_saves`, bumped by Save and Forget), so any of them

   endpoint is on duty, so nothing is "loaded", no idle timer is armed and
   **Unload now** is not drawn. `Slot::Elsewhere` is gone; `Slot::Keyed`

   by the host (a count of pieces whatever the server calls a token). A
   swap clears a finished check's result (found live, deviation 9).

## Deviations from the document, and why

1. **The key is read on first need, not when the engine is built** — the
   `CLAUDE.md` rule above.
2. **`Unavailable::NoKey`** (not in §4.3): an OpenAI-compatible endpoint
   whose account has no key. `engine::refusal` already refuses that as
   `NoKey` once the page has looked; the host needs a value for the case
   where it reads the store before the page has (the first Check from a
   fresh launch). "Send it without a key" would have been the alternative,
   and the product has never done that.
3. **`KeyUnreadable { reason }`** and **`Redirected { to_origin:
   Option<String> }`**: the store's words, and a 3xx with no `Location`.
4. **The read timeout uses `ureq::unversioned::transport`.** ureq 3's stable
   API has only a *total* body timeout, which would cut off a long answer
   that keeps talking; §4.1 asks for a read timeout. `IdleRead` wraps the
   default connector's transport and caps every wait for input at
   `timeout`. That module is outside ureq's semver promise; `Cargo.lock`
   pins 3.4.1, and a change there is a compile error, not a silent one.
5. **File layout**: the payload readers live in `openai.rs`/`ollama.rs`
   beside their bodies; `sse.rs` holds both framings, the accumulator and
   the verdict; `tests.rs` is a sixth file in `http/`.
6. **The new catalogue keys are `settings-engine-remote-*`**: the
   document's natural `settings-engine-endpoint-title` was already the URL
   row's title.
7. **A consumer that dropped its sink loses the stream, not the answer**:
   the engine keeps reading and returns the whole completion, because a
   partial `Ok` is what the document forbids and a cancel is the caller's
   way to stop.
8. **RED first, partly.** The app tests (`engine_for_builds_an_http_engine_for_an_endpoint`,
   `a_key_for_a_plaintext_remote_endpoint_never_reaches_engine_for`, the
   grown `every_refusal_has_a_sentence_in_every_language`,
   `the_check_on_an_endpoint_says_where_its_prompt_went`,
   `an_endpoint_check_reports_its_first_piece_and_its_pieces`) were written
   first and failed to compile against the old code. The engine's §5 tests
   were written in the same pass as the engine and passed on their first
   run; that they can fail is shown by the mutations below, every one red.
9. **Two fixes found by the live check**, each with a test that goes red
   without it: the URL row had been retitled "The endpoint" by my own key
   rename (`no_row_is_titled_like_the_block_above_the_rows`), and a
   finished check's line survived a rebuild for different settings
   (`a_check_result_does_not_outlive_its_engine`). The running binary
   still had both; the fixes are in the commit, not seen in a window.
10. **Tests beyond §5**: six `sse` unit tests (CRLF/LF, comments and
    fields, a payload split across reads, an error in the stream, a quoted
    unreadable payload, Ollama's length and count), `a_redirect_names_only_an_origin`,
    `the_engine_reports_what_it_is_and_where`,
    `an_endpoint_check_reports_its_first_piece_and_its_pieces`,
    `an_endpoints_key_is_read_when_first_asked_and_not_at_startup`,
    `a_check_result_does_not_outlive_its_engine`,
    `no_row_is_titled_like_the_block_above_the_rows`, and the ignored
    `a_real_endpoint_answers_cancels_and_repeats_itself`, which returns
    with a line saying so when `WIPEMARK_TEST_ENDPOINT` is unset — gate 11
    runs every ignored test of the crate with no server beside it.
11. `an_endpoint_is_not_served_from_here_yet` and `duty::ENDPOINT_NOT_YET`
    were removed (the first replaced by the §5 test); `EngineHost::can_load`
    is `can_check`.

**How the key got there, honestly.** The first key was typed into the
field by XTest while the desktop's active layout was Russian, so the
keystrokes became Cyrillic letters; the page stored them, and ureq refused
the non-ASCII header value before anything was sent — the error above,
with no key in it. A second attempt locked the keyboard to its US group
for the typing; GNOME moved focus away during it, the Settings window lost
its place, and those 29 keystrokes (the throwaway llama-server key) and a
click landed in a Chrome window (a GitHub branches page, no visible
effect) rather than in the field. I stopped synthetic typing there, put
the keyboard back on its `ru` group (verified), and wrote the right key
through the same `Vault::set` the Save button calls, from a throwaway
program in the scratchpad; then flipped Provider to Ollama and back with
two clicks to rebuild the engine (which had kept the garbled key), and
every click after that was gated on Settings being the active window.

Afterwards: the key deleted from the credential store (`Vault::delete`,
then `has: false`), the application killed, the server killed,
`ss -ltn` showed nothing on 5056 or 8089, and no `wipemark` or
`llama-server` of this run remained. The app was not launched a second
time.

## Unfinished, stated as unfinished

* **A key with a non-ASCII character** is accepted by the page and stored,
  and only the request says "authorization header is not a string". The
  Save button could refuse it with a sentence of its own; not done here.
* **The two fixes of deviation 9 were not seen in a window**: the run's
  binary predates them; their tests are the evidence.
* **The "sent to <origin>" line was not seen live**: the only endpoint
  here is this machine. `the_check_on_an_endpoint_says_where_its_prompt_went`
  covers it.
* **No Ollama was checked** (none here, §7); the Ollama format is covered
  by the fake server only.
* **Seed reproducibility across a cancel** on llama.cpp's server: one run
  in three differed (above); not investigated.
* **The page's key Save under the real Secret Service** was exercised only
  with the garbled key; the correct key was stored by the same `Vault::set`
  from outside the window.
