## What was built

1. **`inspect(bytes) -> Result<ImageReport, ImageError>`** —
   `crates/wipemark-image/src/lib.rs`. Every metadata block with its
   kind, chunk name, key (PNG keyword or JPEG segment identifier),
   offset, length and evidence; `has_c2pa()`, `has_ai_metadata()`;
   `not_established` with all three of core's ids. Never modifies
   anything.
2. **`strip(bytes, &StripOptions) -> Result<(Vec<u8>, StripReport), ImageError>`** —
   the kept blocks concatenated byte for byte (`concat`), the MPF
   refusal for JPEG, the RIFF size and `VP8X` bits for WebP
   (`webp::rebuild`); the report from a second `inspect` of the output
   (`finish`). Nothing selected → the input, unchanged, no rebuild.
3. **Three parsers that tile the file** — `png.rs`, `jpeg.rs`, `webp.rs`;
   every byte in exactly one block (`tiles`, a debug assertion on every
   parse). JPEG handles fill bytes, stuffing, RSTn, progressive scans,
   trailers after EOI; PNG treats unknown critical chunks as structure
   and reads `tEXt`/`zTXt`/`iTXt` (inflated with a 16 MiB limit) and
   ImageMagick's hex profiles; WebP keeps pad bytes with their chunk.
4. **`signatures.rs`** — `KEYWORDS` (7), `TEXT` (12), `SOURCE_TYPES` (3),
   `C2PA_REFERENCE`, every entry with its evidence sentence; `Generator`
   and `SourceType` with stable ids.
5. **Errors as values** — `Defect` (11 variants), `Unsupported`,
   `ImageError::NotYet` for TIFF/HEIC/AVIF.
6. **Fixtures** — four real files from `contentauth/c2pa-rs`
   (`fixtures/image/`, README with origin, commit, sha256 and licence) and
   twenty injected cases built in `tests/support/`.
7. **Documents** — `docs/plan/E11-1-image-metadata.md` (written first),
   `docs/architecture/images.md` (new), a row in `docs/README.md`, the
   `image/` paragraph of `fixtures/README.md`, three lines of
   `.gitattributes`.

Tests: 19 unit (lib, signatures, text, png, jpeg), 13 in
`tests/signals.rs`, 5 in `tests/pixels.rs`, 10 in `tests/malformed.rs` —
47, all green.

## Deviations from the task, and why

| # | the task | what was done | why |
|---|---|---|---|
| 1 | `keep_non_ai_metadata`, `strip_all_metadata` knobs | one enum, `Scope::{AiProvenance, AllMetadata}` | two booleans with a meaningless fourth state (I4) |
| 2 | E0's `MetadataKind` | added `Rendering` and `Other` | colour must be listed and never removed; non-text metadata (`pHYs`, `tIME`, `PSAI`, trailers) needed a name (I3) |
| 3 | E0's `MetadataFinding { kind, chunk, offset, len }` | added `key` and `evidence` | the task asks for "which field/value or which signature matched"; `key` says which text chunk or which APP1 a block is |
| 4 | E0's `ImageError::Malformed { detail: String }`, `NotImplemented(&str)` | `Malformed { defect: Defect }`, `Unsupported { what }`, `NotYet(ImageContainer)`; `ImageError` is now `Clone + PartialEq` | only applications localize: a `String` is a sentence the library already chose (I11) |
| 5 | "`strip_all_metadata` removes every non-essential chunk" | colour (`Rendering`) is kept by every scope | removing a profile changes how the picture looks while the gate cannot see it (I3) |
| 6 | "editing inside XMP is out" | EXIF and IPTC are not edited either — a block is kept or removed whole; a camera EXIF whose `Software` names a generator goes whole | the same reason: a second writer for a second format |
| 7 | "decode with `png`, `jpeg-decoder`/`zune-jpeg`, `image-webp`" | `png` 0.18, `zune-jpeg` 0.5, `image-webp` 0.2, `sha2` — dev-only | all four already in the lock through gpui; `Cargo.lock` gained edges, no package |
| 8 | "a crate for EXIF/XMP reading is acceptable if justified" | none; one runtime dependency, `miniz_oxide`, for inflate | EXIF/IPTC/XMP are searched as bytes in three encodings, which reads `UNICODE` `UserComment` without an IFD parser; zlib is the one thing that cannot be searched |
| 9 | "for real C2PA, take sample assets" in each container | a real manifest in JPEG only (`c2pa-jumbf.jpg`); PNG `caBX` and WebP `C2PA` carry **that** manifest's JUMBF, injected | the project's PNG and WebP samples with manifests are over 100 KB (`sample1.png` 299 KB); the bytes inside the chunk are a real manifest store either way |
| 10 | `fixtures/images/` | `fixtures/image/` | the README already said so (I14) |
| 11 | — | XMP `dcterms:provenance` is a C2PA signal (`C2paReference`) | two of the project's own samples carry exactly that after their manifest was removed; a pointer binds the file (I7) |
| 12 | — | a JPEG with `MPF` refuses a removal after the MPF header | its offsets would move the secondary pictures (I8) |
