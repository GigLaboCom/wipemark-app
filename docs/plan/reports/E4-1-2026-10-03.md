## Deviations, choices, and why

| # | what | why |
|---|---|---|
| 1 | **One paragraph per chunk, never merged** — D70 says "one or more consecutive paragraphs". | The owner's "rewrite by paragraph" (2026-10-03), as the prompt states it. D70's text should be restated (below). |
| 2 | `。！？` end a sentence **with or without** whitespace after them; `.!?…` need whitespace. The prompt's "(… and CJK `。！？` followed by whitespace)" read literally would leave a Chinese paragraph unsplittable. | CJK prose has no spaces between sentences. Implemented the working reading and say so; `cjk_sentences_split_without_whitespace` pins it. |
| 3 | Glue placeholders are shown **at the start of a line** (`item one\n⟦1⟧item two`); the glue itself still holds the newline + marker + indentation, and restore drops whitespace touching glue. | The model sees a list as a list; a model that keeps, drops or doubles the newline gives the same document back. |
| 4 | `RestoreError::OutOfOrder` for **glue** placeholders (not for others). | A list whose items came back reordered across their glue would carry `2.` before the third item. `PlaceholderGuard` does not check order, so restore must. |
| 5 | `restore` drops the candidate's leading and trailing whitespace. | The chunk's text has none and the bytes around a chunk are the source's; a trailing `\n` from a model would otherwise break a list or a quote. |
| 6 | The lexical scan reads the whole piece, not only the gaps between structural spans; overlapping spans merge. | Found by the property test: a `[[[` whose third bracket was a link's opener was shown as prose `[[` + placeholder, and the context wrote `[[[BEGIN` back together. |
| 7 | A piece with **no letter outside its placeholders** is not a chunk. | A paragraph that is only a link or `1999.` has nothing to rewrite; a call that can only fail costs minutes on a CPU. |
| 8 | HTML `<code>…</code>` inside text is one protected span (and can start a piece), not a piece boundary; HTML list items are separate chunks (the glue rule is Markdown's). | "Kept whole" without cutting the sentence around it; HTML lists have no marker bytes to glue. |
| 9 | An HTML tag that never closes runs to the end of the document and everything after it is kept. | A browser's tokenizer does the same; and the first version (a `<` that does not close is text) was quadratic: 29 s on 700 KB of `<a <a '`. |
| 10 | Plain text protects backtick spans on one line too. | D68 lists inline code; chat output carries backticks and nothing parses them. |
| 11 | The context is capped at a quarter of the budget (then the last sentence alone, then its tail after `…`). | A 400-word sentence is "two sentences" too; the context is for continuity, not a second text. |
| 12 | `detect` carries short **rival** stop-word lists (fr, es, it, pt, nl; uk, bg) and Ukrainian's letters `і ї є ґ`, used only to answer `None`. | The prompt asked for en/de/ru lists; without rivals, Afrikaans read as German and a Ukrainian text without Ukrainian stop words as Russian (both are tests now). |
| 13 | Markdown options beyond the minimum: footnotes (references protected, definitions rewritten), task lists (the box stays in the glue), strikethrough, GFM alert quotes, TOML front matter. | Each one turns syntax a model could damage into structure. |
| 14 | No fixture files. | `wipemark-core`'s `every_fixture_is_asserted` walks `fixtures/text/`; the inputs live in the tests. |

## The token estimate: calibration

`llama-server` (`$S/llama-server-build/bin/llama-server -m
$S/models/Qwen3-4B-Instruct-2507-UD-Q4_K_XL.gguf --port 18089 -c 2048 -t 2
-ngl 0`), `POST /tokenize` per paragraph; the server was killed
afterwards. Rule chosen: ASCII letter/digit 0.31, Cyrillic 0.42, CJK
letter 0.75, whitespace 0, anything else 1.0 — summed in thousandths and
rounded up. Search: a grid over per-class weights, the constraint "no
paragraph under 0.95 of the real count", minimising the mean ratio. A
per-word rule (1 + length beyond *n* × *w*) was tried and did no better
(mean ×1.23 vs ×1.20) — English's whole-word tokens and German's split
compounds pull in opposite directions.

## What E4-3 (the loop) should know

- **Order.** Layer A `clean` the document **first**, then `prepare` the
  cleaned text with `Budget::for_context(engine.info().ctx_len)`; per
  chunk, E4-2's assembler gets `chunk.text`, `chunk.context` and
  `chunk.has_protected()`; Layer A cleans each candidate; the guards run
  with **`chunk.text` as the source** (placeholders and all — that is
  what `PlaceholderGuard` expects); then `Prepared::assemble` with
  `Some(winner)` or `None` per chunk; then the final Layer A pass over the
  assembled document.
- **A `RestoreError` is a rejection**, like a guard's. `OutOfOrder` is the
  one restore can raise that `PlaceholderGuard` cannot: consider a
  `RejectReason` for it (E1's enum is `wipemark-core`'s), or treat it as
  the loop's own.
- **Chunks are independent**: the context is from the source, so chunks
  can be rewritten in any order, and a failed chunk is simply `None`.
- `TextFormat::Code` yields **no chunks** — the loop has to say "nothing
  to rewrite" (or run the `code` tactic, which needs its own preparation).
- `Prepared::language() == None` means the English set plus the "do not
  translate" clause (D64) — and no `back_translate`.
- `est_tokens` overestimates English by ~1.4× and everything else by
  ~1.1–1.3×: good for packing and for a conservative price, not for a
  `max_tokens` sent to an engine (use a multiple of the real input there).
- The list glue is shown on a line of its own; the bench (E4-5) should
  measure whether models keep glue placeholders as well as inline ones.
