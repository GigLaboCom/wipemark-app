### `synth` — the public API

```rust
pub use crate::calibrate::{from_linear, to_linear, BlendModel};   // BlendModel { Encoded, LinearLight }
pub enum LogoColor<'a> { Global([f32; 3]), PerPixel(&'a [[f32; 3]]) }  // per-pixel: the map's own grid
pub enum Rounding { Round /* default */, Truncate }
pub struct Blend<'a> { pub logo: LogoColor<'a>, pub model: BlendModel, pub k: f32, pub bias: [f32; 3], pub rounding: Rounding }
impl Blend<'_> { pub fn encoded(logo: [f32; 3]) -> Blend<'static> }   // the defaults: composite's blend
pub fn composite_with(raster: &mut Raster, map: &AlphaMap, rect: SubRect, kernel: Kernel, blend: &Blend<'_>);
```

`composite_with` places the map by `geometry::shape_with` (the search's own
resampling, so a sub-pixel rect and every `Kernel`), multiplies `α` by `k`
(clamped to 1), blends per colour channel in stored code values or — in
`LinearLight` — `from_linear(α·lin(L) + (1 − α)·lin(O))`, adds the bias,
rounds or truncates, clamps; it never writes alpha. A `PerPixel` logo is
resampled with the map, weighted by `α` (`α·L` and `α` shaped alike, one
divided by the other); one of the wrong length draws nothing. At its
defaults it is `composite`, sample for sample. The catalogue still refuses
`linear-light` and `logo_map`; nothing in `catalogue.rs` moved.

### `recon_bench` — the command line

```
recon_bench pin     --manifest bench/manifest.json [--photos DIR]
recon_bench gen     --manifest bench/manifest.json --out bench/out/<run>
                    [--seed S] [--sample N] [--groups flat,text,photo] [--rows v1-48,…] [--photos DIR] [--jobs N]
recon_bench run     --in bench/out/<run> --config R0 [--config …] --out <results.jsonl>
                    [--export-crops DIR] [--jobs N] [--slices png,jpeg420-q95,…]
recon_bench configs
```

* `pin` makes every background's tile and writes its sha256 and its zones
  (per row: mean, min and max per channel under the mark, and the tone they
  read as) into the manifest; with `--photos` it first lists an empty photo
  group's files with their sha256.
* `gen` makes the tiles again and **refuses** (exit 2) one whose sha256 is
  not the pinned one — checked here by flipping every pin in a copy of the
  manifest: `flat-030: tile sha256 "cc7f…", the manifest pins "0cc7…": the
  generator moved; run pin and commit`, exit 2. A `--seed` other than the
  manifest's runs unpinned and says so. `--sample N` is a fixed-seed sample
  of `N` per group, stratified by tone.
* `run` writes one JSON line per file and config (`run_case`/`one` in the
  example), then `<out>.run.json` (the commit, `+dirty` when the measured
  crates differ from it, the time, the jobs, the files per slice).

The layout of a run, the rows, cases, slices, metrics and gates are in
`scripts/bench/README.md`; the host's commands too.

## Finding: D154 does not hold through the search

The document's test `a_k_of_0_93_is_refused_by_a_k_of_1_profile` fails on
the code at `eca0108` (no restoration code was touched here). A V1-48 mark
drawn at `k = 0.93` over the first procedural gradient at 1024 is refused by
its row (`Gain`, `k* = 0.92`); then the search, which runs whenever no row's
mark was proved, refines it to `(944.125, 943.875, 48.0)` — an eighth of a
pixel off — where `k* = 0.96`, inside the profile's `gain` of 0.06, proves
it and restores it with `k = 1`. V2-36 does the same by shrinking the size
(35.875, 35.625).

Measured by `a_weaker_mark_through_the_rows_and_the_search`
(`tests/measure.rs`, `#[ignore]`; `cargo test -p wipemark-pixels --release
--test measure -- a_weaker --ignored --nocapture`), 8 procedural kinds × 3
seeds, 1024²:

| map | k | refused | proved at the row | proved by the search | not seen | of the restored: outline said | off the picture by up to |
|---|---|---|---|---|---|---|---|
| V1-48 | 0.90 | 10 | 0 | 13 | 1 | 6 | 25 levels |
| V1-48 | 0.93 | 12 | 0 | 11 | 1 | 5 | 15 levels |
| V1-48 | 0.95 | 12 | 10 | 1 | 1 | 0 | 11 levels |
| V2-36 | 0.90 | 12 | 0 | 9 | 3 | 2 | 18 levels |
| V2-36 | 0.93 | 8 | 1 | 12 | 3 | 4 | 12 levels |
| V2-36 | 0.95 | 9 | 11 | 1 | 3 | 0 | 8 levels |

So a mark 7–10 % weaker than its profile is restored about half the time,
with `k = 1`, leaving a ghost of the mark up to 12–25 levels off the truth,
and the outline check says so in fewer than half of those. At `k = 0.95`
the row itself accepts it (`|0.96 − 1| ≤ 0.06`) — that is the tolerance
working as designed. The mechanism: the search's refinement (D236) picks
the place and size where the residual at `k = 1` is smallest, and a
template moved by an eighth of a pixel or shrunk by a quarter is a weaker
mark — it compensates the opacity, which NCC never did. The bench's `R-k`
composites measure the same on every slice (smoke, §7 of its report: 6–14
of 48 `R-k` files proved by the search per slice, 0 at the row).

This is a `detect`-route question, not R5's to change (`propose.rs` and
`verify.rs` are out of scope). The test stays in the tree, ignored with its
reason, so that the change that answers it can un-ignore it. See Q1.

## Questions

* **Q1 (D154).** A mark 7–10 % weaker than its profile, refused by its row,
  is proved by the search's sub-pixel or size refinement about half the
