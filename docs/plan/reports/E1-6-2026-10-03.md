## Deviations from the document, and why

1. **Two catalogue keys beyond §4.5's 44: 46 added, 1 deleted.**
   - `cli-report-homoglyphs-kept` — printed under the rows whenever a
     `kept` row is a homoglyph and `aggressive` is off. Without it, a
     homoglyph makes the input suspicious (D4) and `clean` exits **1**
     beside a result that did not change, with only a "Kept:" heading
     to explain it. The coordinator asked that surfaces say "found, not
     replaced" in that case; the line says that, and that the
     replacement is "the look-alike letter of its word's own script" —
     never ASCII (E1-4: U+043A → U+0138, β → ß). Gated by
     `a_homoglyph_left_in_place_is_said_to_be_found_and_not_replaced`.
   - `cli-clean-later` (`$count`) — under `--nfkc`, when the rounds
     after NFKC acted on characters no row lists. Computed as
     (Σ `removed` + Σ `normalized` other than `nfkc`) − Σ `findings`
     counts, which is 0 without `nfkc` (E1-3's counters-agree gate). On
     `survive-emoji-presentation.txt` the report reads "Kept: U+FE0F … 5
     times" and then "2 more characters, uncovered by NFKC, were removed
     or replaced in further passes; they have no position in the input,
     so a row above may still list them as kept." That is the "kept 5,
     removed 2" case of E1-3, said rather than left as a contradiction.
     Gated by `what_the_passes_after_nfkc_did_is_counted`.
2. **`run::Io` holds `Box<dyn Read/Write + 'a>`**, not `&mut dyn …`:
   `Io::standard()` has to own the stream locks it returns; tests pass
   `Box::new(&mut Vec<u8>)` and read the vectors afterwards. Same
   shape, same use.
3. **The third-shelf title has no colon** ("Not established", not
   "Not established:" as §4.4.8's sample shows): the line is the
   existing `report-not-established-title` key, which the document
   reuses and whose text is shared with other surfaces.
4. **`NotText` names a format only when it is not itself textual.**
   Step 6 (`encoding: None` → `NotText`) can produce
   `found: Some(Rtf)`; "the contents are RTF, not text" would be false,
   so such a case gets `cli-not-text-unknown`. `named` (unused by the
   messages) goes to the log as a format name.
5. **A path with no last component** (`..`, `/`) has no "beside";
   `clean` decides the destination as stdout, the read then refuses it
   (folder or missing), and an impossible successful read is refused
   with `cli-is-a-folder` rather than printed. Not reachable on any
   tested platform; written down so it is not mistaken for intent.
6. **Extra tests**: three in-process `run::tests` (stdin cleaned onto
   stdout, empty stdin reported, 8-bit stdin inconclusive) and the two
   of deviation 1. `the_human_report_carries_no_character_layer_a_would_strip`
   also runs `clean` with `aggressive + nfkc` and a UTF-16 encoding so
   every optional line is rendered.
7. **The UTF-16LE-without-BOM case** of
   `a_file_keeps_its_encoding_and_its_bom` puts 2,100 ASCII characters
   before `a` U+200B `b`: intake recognises mark-less UTF-16 only from
   an all-ASCII head (Q-D6), and U+200B is not ASCII, so a three-
   character file could not be the "ASCII" case §5 means.
8. **MCP test inputs carry escapes, not raw characters** (`"a\u200bb"`
   in the JSON request), so the test source carries no invisible
   character; the server receives the decoded character either way.
