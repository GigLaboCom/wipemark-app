## Deviations from the document

1. **The fixtures are classed by what each one is**, not all as
   `recon-png` (§4.1 says "the 21 originals + the 14 crops"). Only four
   fixtures are PNG.
   * `recon-png`: four PNG fixtures (variant `fixture-png`).
   * `recon-jpeg-444`: two fixtures (`fixture-q95`, `fixture-q98`).
   * `recon-jpeg-420`: five fixtures (`fixture-q95`, `fixture-q98`).
   * `transparent`: `crying-transparent-1025.png` and
     `cut-out-confetti-256.webp`. The latter is lossy VP8 with an alpha
     chunk. It is still under L1, because a refused mark writes the
     strip's bytes and nothing restored can move them.
   * A **new class, `recon-webp`**, for `scroll-1040-q90.webp` (lossy,
     so L2's and not L1's).

   Putting a JPEG under L1 would fail every legitimate `lossy` change.
2. **A source can be a folder of this repository** (`"repo":
   "fixtures/image/gemini"`) as well as a Watchword key. The fixtures are
   committed, so a key for them would be a second copy.
3. **`fetch` takes a presigned URL** — from Watchword's `download_file`,
   in `REGRESS_URL_<SOURCE>` or `--url` — or a local ZIP or folder
   (`--local`). The document asks for "the Watchword download endpoint
   (the host's token from the environment)". No HTTP endpoint or token
   scheme for Watchword is written anywhere in this repository; the
   precedent is the MCP's presigned URL and `curl`. The URL is treated as
   a credential: never written to a file, and only its host is printed.
   See Q1.
4. **A `pin` command** (not in §4.2). It fills `null` sha256s from the
   fetched files and adds files by glob (`--add CLASS:SOURCE:GLOB`). The
   sticker and derived sha256s cannot be computed without the ZIP, so the
   committed manifest has `null` there. `baseline` and `run` refuse an
   unpinned manifest.
5. **`scripts/golden-manifest.py`** writes the 413 entries. It keeps every
   sha256 and `expect` already pinned for an entry whose definition did
   not change, and anything `pin --add` added. A hand-typed manifest of
   this size is how a recipe drifts.
6. **Derived files carry `crop` and `resize`.** They are applied after
   `convert("RGB")`, crop first, as `repro.py` does. `resize` is an
   explicit `[w, h]`: ×0.9 is 1843², ×1.1 is 2253².
7. **`frames` has six variants per crop.** For each of 1025, 1040 and
   1024 there is a PNG and a 4:2:0 JPEG at q95 and q90. The §6.3 claims
   ("1040 equal to 2048") were measured on the JPEGs.
8. **`recon-resized` is included** although it is not ●. Its recipe is
   one line, and it has no rule.
9. **`expect` is written by `baseline` into the manifest** (it can be
   switched off with `--no-write-expect`). `run` refuses a baseline whose
   records disagree with it, because the two were taken apart.
10. **G1's "nothing written"** is read as "pixels not written"
    (`encoding.kind` `unchanged`). `wipemark-cli clean -o` always writes
    the stripped copy of a picture with no mark (`cli.md`, "Images"). G1
    fails a negative on any increase in `found`, `verified` or `restored`,
    on a clean exit that leaves 0, or on pixels written.
11. **G2's "3→0" is read as 3→0 or 1.** A mark proved and fully restored
    exits **1** (`cli.md`), never 0. "Within its bound" uses the product's
    constants, mirrored from `verify.rs`: `OUTLINE_BOUND` 0.20,
    `STEP_LEVELS` 1.0, `CHROMA_LEVELS` 4.0, `TEXTURE_LEVELS` 5.5. Every
    other per-file exit change is **attention**; the corpus count is what
    fails.
12. **G3 compares `holes` and `clamped` only where both sides restored.**
    A restoration that is new (a lifted refusal) is L3's and G2's to
    judge. Otherwise every lifted refusal would fail on "clamped grew from
    nothing".
13. **D4 alone (`detect` without `lossy`) is `recon-png`'s**, as §4.3 says.
    With `lossy` in the set, L1 covers every lossless class, excused only
    where `detect` moved the rect.
14. **Routes combine**: `--route lossy,detect`, and `all` is the three.
    With `model` in the set, L1 and D4 do not apply (M1). That is why the
    end-to-end diffs each route alone as well.
15. **A change states its target with `--target MEASURE@SELECTOR`**
    (`chroma@recon-jpeg-420:q95,q90`, `found@frames:c1024-*`, `rect@id=…`).
    §4.3 speaks of "the change's target measure", "targets" and "files the
    report names" without saying how a run is told. Without a target, L2,
    D1 and M3 check only "not worse" or "not lost".
16. **Time**: ×1.5 is attention only for a file that took at least
    0.25 s before (`TIME_FLOOR_S`, `[tunable]`), against timer noise. §4.2
    has no floor.
17. **`summary.json`** is `{schema, before, after, corpus, files[]}`. Each
    file object has §4.2's fields plus `inspect_exit`, `verified`,
    `restored` and `time_s`. `corpus` holds the corpus gates, the lifted
    refusals, the known false positives, and the missing and new files.
18. **`run` and `diff` exit** 0 (all pass), 1 (a fail), 2 (a refusal) or 3
    (attention, no fail): the repository's four.
19. **`index.json`** adds:
    * `cli_tree` and `script_commit`: a baseline at an old commit is run
      by this tree's script over a CLI built there, and `commit` is the
      CLI's tree's (found from `--cli`'s path, or `--cli-tree`);
    * `picture_crates_dirty`;
    * the zlib and libjpeg-turbo versions (libjpeg "6.2" is only the API
      level);
    * the platform;
    * the manifest's sha256.
20. **In a record, the clean JSON's `written` path is a bool.** The path
    is a temporary folder that differs run to run. Comparing it would fail
    L1 on every file.
21. **"Equal up to the printing of floats"** is relative 10⁻⁶. The two
    folders' JSONs are compared whole: inspect's, and clean's with
    `written` normalised.
22. **A file with several restorations** is reduced per measure:
    * `outline`, `chroma`, `texture`, `consistency_px`, and
      `out_of_range` over `found[]`: the largest;
    * `step`: the largest in magnitude, signed;
    * `holes` and `clamped`: summed.

    "Not worse" is judged on magnitudes, so a sign is not a measure.
23. **The §6.3 checks.**
    * Ranges leave `11_crying` out, as the 2048 report's did.
    * The refused shares are held within 0.1 **percentage points**, the
      literal "within 0.1". That is loose against figures quoted to a
      hundredth, and the actual numbers are printed beside each check.
    * "1040 equal to 2048" is checked at 4:2:0 q95 and q90. It compares
      the exit, the verdicts, the refusals, and every measure but
      `clamped` and `holes` to 0.005 (the share in percent).
24. **Seven selftest cases beyond §5's seven**, and the end-to-end case
    under `--cli`. §5 says the selftest has no CLI; it still has none
    unless `--cli` is given.

* **The ZIP's layout is written two ways.** §3 says

* **"libjpeg 6.2"** is the API level Pillow reports. The library that

## Questions

* **Q1 (owner):** does Watchword have an HTTP download endpoint a host
  script can call with a token from the environment? Until it does,
  `fetch` takes the presigned URL from `download_file`, which the host
  asks for through the MCP tool.
* **Q2 (host):** the ZIP's layout. Is it `stickers/transparent/*.png` or
  `transparent/*.png`, and what exactly are the two alternates' paths?
  `unzip -l` answers it. The `--add` globs under "For the host" are
  written for the first layout.
* **Q3 (engineering):** derived **PNG** bytes depend on Pillow's zlib
  (1.2.13 here). A host with the same Pillow wheel gets the same bytes,
  and another build may not. D304 asks for sha256, so a derived PNG is
  refused on another zlib even with equal pixels. Should derived PNGs be
  held to their decoded pixels instead? The script keeps the sha256 for
  now.
* **Q4 (coordinator):** confirm the readings in deviations 10, 11 and
  12. They decide what a `lossy` change that lifts D252's refusals
  reports.
* **Q5 (coordinator):** the baseline's commit. Building at `4b5ba17`
  needs a worktree there, because the script is not in that tree, but the
  crates are identical up to this branch. The simplest is to build the CLI
  at the commit R1 is merged as and file the baseline under it. `baseline`
  refuses an `--out` named after a commit that is not the CLI tree's HEAD.

## Decisions proposed

* **D303 (routes and gates)**, confirmed with these amendments:
  * routes combine (`lossy,detect`), and `all` is the three;
  * with `model` in the set, L1 and D4 do not apply;
  * a change states its targets as `MEASURE@SELECTOR`;
  * G2's improvement is 3→0 or 1, with the product's bounds;
  * G3 compares only where both sides restored;
  * per-file exit changes are attention, and the corpus count fails;
  * `run` exits 0/1/2/3;
  * time is attention past ×1.5 above 0.25 s.

  Every number is `[tunable]`, at the top of `scripts/regress.py`.
* **D304 (corpora)**, confirmed with these amendments:
  * a source is a Watchword ZIP (`key`, `sha256`) or a folder of this
    repository (`repo`);
  * a manifest may carry `null` sha256 until `regress.py pin` fills them
    on the host, and a run refuses an unpinned or mismatched file;
  * derived files carry their recipe (`recipe`, `quality`, `subsampling`,
    `crop`, `resize`) and are refused by the Pillow, libjpeg-turbo and
    zlib found;
  * `expect` is written by `baseline` and checked by `run`.
