## What was built

### 1. The bench takes a profile (`crates/wipemark-picture/examples/recon_bench.rs`)

* **`gen --profile ID[,ID]`.** A Gemini id keeps that profile's rows of the
  six-row table (`ROWS`, unchanged); with neither `--profile` nor
  `--catalogue` the bench is what it was. Any other id gets rows **read off
  its own placements** (`derive_rows`): one per size — `--sizes WxH,…`, or
  the least size each placement's `when` allows (1024 where it says
  nothing) — each the profile's first placement at that size, exactly as
  `place` (and the product) takes it. A row is `canonical` when it sits at
  its map's own size, not resampled, with a map not fitted; `shipped`
  otherwise. Ids are `<map>-<W>x<H>`. A profile with a search and no row is
  refused by name: the bench draws a mark at a row's place.
* **`--catalogue FILE`** (gen and run), through
  `examples/support/catalogue.rs` (shared by `#[path]` with
  `measure_clean`): a catalogue in the shipped schema, parsed by
  `Catalogue::parse` with every check the shipped one passes, its `.wma`
  maps found by file name beside it or one folder down (the rule
  `wipemark-pixels/build.rs` compiles by), then among the shipped assets —
  so a copy of `marks.v1.json` with a provisional row added reads with only
  the new maps beside it. The catalogue still refuses `linear-light` and
  `logo_map` (§0.2). `Cat::File` is the cases' third catalogue; the run's
  `manifest.json` records the file and its sha256, and `run` reads the same
  file back (or `--catalogue`) and refuses one whose sha256 moved.
  `--export-crops` takes the opacity from the case's own catalogue.
* **A tile in the mark's corner.** The 512-pixel tile goes in the corner of
  the canvas nearest the mark's box (`tile_origin`); every Gemini row is
  bottom-right, so a Gemini run's canvases are what they were (the test
  pins it). Rows of one size whose marks want different corners are refused
  (run them apart with `--rows`).
* **Degradations per profile.** `gen --slices a,b` or `gen --degradations
  FILE` — `{"schema": 1, "profile": ID|null, "slices": […], "comment": …}`,
  the degradations a vendor actually hands out (R2 stage 0) — names the
  slices; besides §4.3's, any `jpeg444-qNN`/`jpeg420-qNN` (1–100) is a slice.
  The list is recorded in the run's `manifest.json`; `image`'s JPEGs are
  written for the 4:4:4 ones named (q95 and q90 when none is named, as
  before); `scripts/bench/encode.py` writes Pillow's for the list alone and
  only the resized truths it needs; `run` takes the list unless `--slices`
  overrides it. A list naming another profile than the run's is refused.
* **The matrix (A5) for any profile.** Every row of every profile is
  composited `encoded` and `linear-light` (and `R-k` on a canonical row);
  nothing in `cases` was Gemini's. `report.py` gained `--profile GLOB`
  (report and gates keep one profile's lines out of a concatenation) and §0
  names the profiles and the catalogue file.
* So **`R0-grok` is `R0`** over a run generated with `--catalogue <file>
  --profile <grok id> --degradations <grok list>`, and `R6`, `R7`'s column,
  `R8d/p/w` run on it unchanged: no config names a profile. Edits to
  `recon_bench.rs` stay away from `CONFIGS` and the config functions (R9's
  `blend-preview` configs land there in parallel); `export` gained a
  `catalogue` argument and `gen_one` a `jpegs` one.

### 2. A synthetic stand-in profile (`fixtures/marks/synthetic-wordmark/`)

`scripts/bench/wordmark.py` (header per `CLAUDE.md`; stdlib, `+ − × ÷` and
`sqrt` only) draws a **text-like 72 × 24 map of straight strokes** — four
glyph-like groups, one-pixel antialiased ramps, peak 0.5, no font file — and
writes it as a 16-bit `.wma` and a `marks.json` with one profile,
`fixture-wordmark` (vendor `fixture`, product `bench`, `status:
"provisional"`), its map pinned by sha256
(`d9ba632c5c3f277810f26520565736cac5f7222b9e95c4d75afb53d463ea6241`), two
**bottom-left** corner rows (≥ 1025: margin 48, 40; any size: 24, 20) and a
bounded search. `degradations.json` beside it is the degradation list's
shape. It is a fixture: it is not Grok's mark, measures nothing and no
figure about a vendor is read off it; `wordmark.py check` holds the
committed bytes to the script. `fixtures/README.md` says so.

### 3. The regression for a second golden set (`scripts/regress.py`)

* **`held-out`** is a class (and in `golden/manifest.schema.json`): R11's
  held-out files, lossless or lossy by their variant as `frames` are; a
  proof lost is G4's fail. `recon-<format>`, `frames` and `negative` already
  existed; a text look-alike is a `negative` (variant `text-…`) and G1 holds
  for it as for any negative. **No `golden/grok/manifest.json` was created**
  (R12 §4.2: only once there are files).
* **`--profile GLOB` / `--foreign GLOB`** (run, diff): every gate reads the
  selected profiles' findings alone, plus **F2** (a file whose found or
  verified count of them fell fails); **F1** fails a file with any finding of
  a foreign profile, with a corpus gate of each. R11's P5 is then a diff:
  `diff --a <Gemini baseline before> --b <run with the profile> --route
  detect --profile 'gemini-*' --foreign 'grok-*'`.
* **The §6.3 reproduction is the Gemini stickers'.** `baseline` checks
  D247/D250/D252 over the files of `wipemark-gemini-stickers-2026-10-04` and
  those derived from them (`reproduce_scope`), and on a corpus with none
  says so: otherwise a Grok `recon-jpeg-444` q95 would be held to D250's
  8.59–9.22 and `baseline --golden golden/grok` would exit 1. On the Gemini
  corpus nothing changes (its fixtures' variants never matched the checks).
* Three selftests, one per new behaviour (below); the header carries the
  Grok runbook.

### 4. `measure_clean` for any profile

It took a profile by id from the compiled-in catalogue only. It now takes
`--catalogue FILE` (the same road), used for the examination that finds
what to avoid and for the rectangles. And a non-square map was measured on
a **square** (`height: side`): the rectangle is now the map's width by its
height (`rect_height` in a row; a row written before reads back square). So
"the same over R11's held-out Grok files" runs with `--catalogue <grok>
--profile <grok id>` and no change of code. The measures **after** a
restoration are the CLI's own (`restored[]` of `clean --json`), which
`regress.py baseline --golden golden/grok` collects once the profile is in
the build the CLI runs.

## The runbook, in short (host)

1. Build at the commit under test with the zune-jpeg fork:
   `cargo build --release -p wipemark-picture --example recon_bench --locked`
   (and `-p wipemark-cli` for the regression).
2. Commit `bench/degradations/grok.json` from R2 stage 0's facts.
3. `recon_bench gen … --catalogue <R11's provisional marks.v1.json> --profile <grok id> --degradations bench/degradations/grok.json [--sizes …]`,
   `encode.py`, `recon_bench run --config R0 [--config R6 --config R8d …]`
   (R0-grok and the accepted configs, unchanged), `report.py report` — §2 is
   the matrix.
4. P5: `regress.py diff --a <Gemini baseline before the profile> --b <run with it> --route detect --profile 'gemini-*' --foreign 'grok-*'`.
5. `measure_clean list … --catalogue <file> --profile <grok id>` over the
   Grok negatives and Gemini's; the rule p99 + 20 % against the constants.
6. After acceptance: `golden/grok/manifest.json`, `regress.py baseline
   --golden golden/grok …`, then `run --golden golden/grok --route all`
   against itself, 100 % pass.

The full commands are in `scripts/bench/README.md` ("Any profile") and
`scripts/regress.py`'s header ("The Grok runbook").

## Deviations

* The task asked for the red checks to be seen; the rule changed during the
  round and none was run. They are in the table above and below, to run
  centrally.
* `measure_clean` gained a row field, `rect_height` (a tool's format, not
  the product's), because a non-square map was measured on a square.
* The tile's corner moved from "always bottom-right" to "the mark's
  corner"; for every Gemini row the two are the same.
* `regress.py`'s §6.3 reproduction is now scoped to the stickers' source
  (a behaviour change only on a corpus without it).
