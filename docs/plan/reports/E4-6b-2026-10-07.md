## 3. Decisions D310–D326

- **D310** — `EngineSource::for_item` is blocking and asked on the queue's thread when an item starts: the application's answer may read a key (blocks), and the queue's thread is the one place waiting costs nothing visible. The engine is held by the job and dropped when it ends, so the application's `for_job` counts the item busy for its whole length.
- **D311** — nothing on duty or `Unavailable` (also mid-job) holds the queue instead of failing the item; the hold lifts on a duty change (`EngineHandle::when_changed`) or Resume, never by a retry loop — asking an endpoint reads the keychain.
- **D312** — a journal row is metadata: name, path (the person's own database), kind, format, encoding, size, verdict and counts, where the result went. The vocabulary (`Origin`, `Action`, `Phase`, `Entry`) lives in `wipemark-store::entry` because two applications write it.
- **D313** — an agent's (or the CLI's) queue item is removed the moment its answer goes back (secure delete); the waiting call writes that row's end, the bookkeeper writes every start and a window rewrite's end, and a start heard late never reopens an ended row (`Journal::update_open`).
- **D314** — `JournalWriter`: read-write, never create or migrate, journal-only by type.
- **D315** — the CLI with no database is silent (a log line); with one it cannot write, one stderr line. A deviation from the task's "a missing … file → one stderr line": a hook running where no application was ever started would print it on every run.
- **D316** — rows of another process by `PRAGMA data_version`, read once a second; in-process writes by a notes channel looked at ten times a second. Polled, not awaited: a GPUI task woken from another thread is not a wake the window's executor scheduled (and the test scheduler refuses it).
- **D317** — at launch: a window clean left mid-way waits again, or with no file behind it is forgotten; a waiting no-file row is forgotten; an agent's or the CLI's rewrite still queued is cancelled and its queue row removed; a window's rewrite is left for the queue, and one whose item is gone failed.
- **D318** — (owner, 2026-10-07) a row nobody asked to process says **Not started**, its tooltip naming what would process it; "Queued" only for a row in a line; with *Process what arrives* set a drop goes straight into a line.
- **D319** — `Destination::New` (only where nothing is, `Undelivered::Exists`) beside `Destination::File` (replace); `Destination::beside` is `name.rewritten.ext` as `New`. The item row's `{"new": …}` is additive; `ITEM_VERSION` stays 1.
- **D320** — one journal row per document; its action is the last asked (cleaned then rewritten is one row).
- **D321** — the CLI's origin, file name, path and size travel in `params._meta` (MCP's own place for what is not an argument); the answer names its row in `result._meta["wipemark/journal"]`; the CLI updates that row with the file it wrote.
- **D322** — an agent's call is answered at once when the queue holds or is paused while its item waits, instead of waiting on a line that is not moving; the ceiling counts from the item's start.
- **D323** — a window's rewrite is an agent's call with no arguments: paraphrase, default intensity, effort by executor, Layer A at its defaults, the saved templates and pivot (`mcp::rewrite::saved_rows`, shared).
- **D324** — the status bar: a model's load progress, then the cleans, then the rewrites (or why they wait), then who is on duty.
- **D325** — (owner, 2026-10-07) Clean and Rewrite are buttons on every row (the Process column), greyed with the menu's own reason; the Actions menu keeps both and the rest.
- **D326** — (owner, 2026-10-07) every badge reads without its tooltip: *No marks found* (tooltip: nothing to remove, nothing written, the file was found and read), *Queued to clean*, *Partly cleaned*, *Clean failed*, *Rewrite cancelled*, *Marks found*, *In progress…*, beside the new *Queued for rewrite* / *Waiting for an engine* / *Rewriting…* / *Rewritten* / *Partly rewritten* / *Rewrite failed*.

## 7. Window checklist for the owner

1. Drop the article on the main window: the row says **Not started**, with
   **Clean** and **Rewrite** buttons on it.
2. Press **Rewrite**: Queued for rewrite → Rewriting… (the tooltip says the
   paragraph) → Rewritten / Partly rewritten; the status bar says "Rewriting
   1 of 1 · paragraph k of n" (and the load percent first, if the model was
   not loaded); `article.rewritten.md` appears beside it, `article.cleaned.md`
   untouched.
3. Double-click the row: Compare shows the rewrite as delivered; edit, then
   **Back to the rewritten text**.
4. Drop three texts, **Rewrite all**: the price (calls, tokens, minutes or
   "unknown"; here or sent away) and nothing starts until Rewrite; **Pause**
   mid-way, **Resume**; **Cancel** one row from its menu.
5. From a terminal: `wipemark-cli rewrite article.md` with the application
   running — a row **From the command line** appears without a click,
   rewritten, its result the file the CLI wrote; `wipemark-cli clean x.md`
   another row; `--no-record` none.
6. An agent's `clean` and `rewrite` — rows **From an agent**, "Handed back
   to whoever asked".
7. Quit and start again: the rows are still there; **Clear finished**
   empties the finished ones; Settings › Retention › *Keep finished rows*.
8. Settings › General › *Process what arrives* = Rewrite, with an endpoint
   on duty: a drop asks "Send … to …?" first.
9. Unload the model / put nothing on duty, Rewrite a row: **Waiting for an
   engine** with the reason; put a model on duty: it starts by itself.
