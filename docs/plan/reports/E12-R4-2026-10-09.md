### The hook

`refine_at` looks the profile up, finds the placement row whose own
rectangle in this raster **is** `rect` (the rectangle `examine` gives a
row's finding), and runs `refinement()` from it with `search` set to that
row's map — the quarter-pixel grid of origins and sizes at reach 4, the
kernels when the mark is under `SHRUNK` of the map, the eighth-pixel grid,
all by the residual the second proof leaves, never NCC. It returns:

| field | what |
|---|---|
| `rect`, `kernel` | the **raw best** the sweeps reached, whether or not it cleared the margin |
| `residual_at` | the residual at `rect` asked about, by the area integral |
| `residual_refined` | the residual at the raw best |
| `kept_by_margin` | whether the search would move there (`refinement()`'s own decision, `≤ (1 − REFINE_MARGIN)·residual_at`) |

A rectangle no row names is refined with the profile's search map.

## Deviations from the document

1. **A second `#[doc(hidden)]` function**, `ring_background`, in
   `calibrate.rs` (the document names one, in `propose.rs`). §4.3 asks for
   `Ô` "as `calibrate` fits it" and for the Python restatement to be
   checked against calibrate's output on one file; §4.4 asks for the same
   quadratic. calibrate's `background` was private. It is now the
   capture-with-a-twin case plus a call to `ring_background`, behaviour
   unchanged (`tests/calibrate.rs` green); `map_regress` calls it, and
   `--background` writes it for `bias.py check-background`.
2. **`Refined` carries `kept_by_margin`** beside the four fields the
   document's comment lists, and its `rect`/`kernel` are the raw best (the
   document: "returns the raw best too"). The CSV's `kept_by_margin` is
   this field.
3. **The row's map is found by matching `rect`** against each row's own
   rectangle in the raster (the document's signature has no row index);
   a rectangle no row names uses the search map. `refine`'s body moved
   into `refinement()` and `rows()`'s rectangle into `row_rect()` so the
   hook runs the same code; the product path is unchanged.
4. **`SHRUNK` is measured against the map `refine` is given.** With the
   row's map (the document's "search set to the row's map"), V1's 96 row is
   refined exactly as the search would refine it (its map is the search
   map), but for V1's 48 row and V2's 36 row the kernel sweep is not
   entered, where the search (comparing with the 96 map) would enter it,
   and sizes other than the row's resample the row's map rather than the
   search's. See Q5.
5. **`refine_at_leaves_a_row_that_is_right` draws the mark 0.06 px off the
   row**, over a gradient with ±1 noise, so that the raw best does move by
   an eighth (gain 1–8 %) and the margin is what is asked; it asserts that
   the sweeps saw a better neighbour, then that what the search would take
   is within < ⅛ of the row. Exactly at the row, nothing can make it red
   (above).
6. **`tests/measure.rs` gains an ignored measurement**, not in the
   document's file list, because the report quotes its figures and the
   repository keeps every script that makes one.
7. **`scripts/analytics/selfcheck.sh`**, not in the document's file list:
   every container figure above comes from it.
8. **`forced_search`**: the rectangles are three columns each (`row_x,
   row_y, row_size`, `refined_x, …`), and a last column `group` (empty
   unless `--list` is given) carries `gemini-midtone`'s group for "its
   gradients and textures apart". The distributions §4.2 asks to compute
   are printed by the tool itself, per profile and size and per group,
   with a mechanical reading (`QUARTER` ¼, `GAIN_LINE` 0.9, `RIGHT_SHARE`
   95 %, a systematic shift: mean ≥ ⅛ and ≥ 80 % one sign — the last two
   `[tunable]` by this step, not the document).
9. **`map_regress`**:
   * the `L` planes are columns of `pixels.tsv` (with `α_reg`, `α_map`,
     `Δα`, `R²`, the count and `Ô`'s sd, min and max), not three image
     files;
   * a sample stored at 0 or the maximum is left out of the fit (clipped,
     not on the line);
   * "spread of `O`" is the pooled within-channel standard deviation per
     pixel, beside its min and max;
   * the reading needs `Ô`'s median sd ≥ 20 levels (`MIN_O_SPREAD`,
     `[tunable]`); its other `[tunable]`s: `O ≈ 0` is `Ô ≤ 8` levels,
     "along the logo" `|corr(ΔL, α)| ≥ 0.5`, "`R²` low" a median under 0.9;
   * the held-out verdict reads the **largest** `|r|` (D240's ~6 was a
     largest); p95 and p99 are printed beside it (Q3);
   * pixels in the D240 residual are those with `α_map` and `α_reg` both
     over 0.1, so both models are measured on one set.
10. **`bias.py`**:
    * the reading is on each bin's **median**: on the fixtures the means
      sat 0.8–2.0 levels under the medians, dragged by a few pixels (sd
      2.0–4.3); a constant would move both;
    * a reading needs three bins of 30+ samples in every channel
      (`MIN_READ_BINS`, `MIN_BIN`, `[tunable]`) — "not readable" otherwise;
