## What landed

A DFlash2 draft beside Qwen3.8 27B, end to end, everywhere but on a GPU:
the seven `llama-ext.h` staging calls through a C++ shim (F1); the draft
loop, a port of llama.cpp's `common_speculative_impl_draft_dflash` at
`b10731`, whose arithmetic is tested with fakes (F2); the draft as a
catalogue entry tied to its model, the Engine page's
`engine.local.speculative` row, the duty that decides whether the draft
goes along, the engine that loads both or the model alone and says why, the
Models card that says it, the command line (F3); the bench's `--draft`, its
speed table and `bench/run-dflash.sh` (F4); and the documents (F5).

How much faster it is, nobody knows yet: that is the host's live gate (c)
and `run-dflash.sh`, with the draft downloaded. Neither the lossless claim
over the real model (live gate (b)) nor the FFI half of the loop has run
against llama.cpp with a model — the container has none — so the host's
checklist below is not a formality.

## Not decided, or decided at a default

* **The vocabulary check.** The task asked "same `n_tokens`, same mask
  token"; this build also compares every token's text from id 5 on (the
  draft's mask excepted), llama.cpp's own compatibility check for drafts
  (which its DFlash loop does not run). If the real draft's GGUF differs in
  a token text the conversion rewrote, live gate (a) shows it as a
  `Vocabulary` refusal beside Qwen3.8; the fallback is the task's literal
  rule (size and mask only).
* **A mask token the target declares.** When Qwen3.8's GGUF names a mask
  token, it must be the draft's; when it names none (expected), the draft's
  must be a token of its vocabulary.
* **`n_max` is 7, not a setting** — the card's figure, clamped to the
  block (8 for this draft). The bench is where another figure would be
  measured first.
* **The draft is offered the model's GPU layers.** One `LoadParams` for
  both; a card with no room for both may refuse the draft's context (now a
  refusal of the draft, D485) or need fewer layers for the model.
* **The engine's own memory check** counts the draft's file and its
  header's cache, not the seven snapshots; the catalogue's figure (2 816
  MiB, from the two `config.json` files) counts them and is what the duty
  and the card judge by.
* **The fingerprint's gap** (D483): a draft refused at one load for a
  reason that does not recur (a context llama.cpp failed to create) and
  loaded at the next could leave a resumed job's records naming a draft
  that did not decode beside every chunk — the same text under greedy
  decoding, valid draws of the same model under sampling.
* **The report's JSON** does not name the draft (the fingerprint does). A
  `"draft"` beside `"model_id"` under `best_effort.engine` would be a format
  change; not made.
* **The CLI's choice of the draft** is the application's rule restated in
  `own_engine` and covered by the listing test only: a test of the draft
  reaching `rewrite`'s engine needs a whole draft file on disk, hashed.
