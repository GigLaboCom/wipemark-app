## Decisions (I-numbers; mapped from D170 by the series report)

| I | decision |
|---|---|
| I21 | **`reframe` is a function of `wipemark-image`, filtered by the same `removes` as `strip`** — so `reframe(x, x) == strip(x)` is a property of one code path, and C2PA leaves on every reframe because both scopes take it |
| I22 | **A colour-type or depth change takes `bKGD`, `sBIT`, `hIST`** and reports them removed — the one way a `Rendering` block leaves, because its bytes would be wrong |
| I23 | **JPEG metadata among the coding segments moves ahead of the new ones**; an MPF JPEG is refused (its offsets point into the old pictures) |
| I24 | **The proof is three checks, all on the output** (decodes to the restored raster; nothing outside the rectangles moved; nothing verifies) — a failure is `PictureError::Proof` and no output |
| I25 | **Interlace is not written** (`png` has no interlaced writer) and the report says `interlace_dropped` |
| I26 | **JPEG and lossy WebP are examined in this step and reported, not restored** (`restorable: false`, every finding a mark left) — the plan's shipping order; E12-4 turns them on |
| I27 | **`PictureOptions.catalogue`** lets a caller (the suites) pass a catalogue; `None` is the shipped one, and a shipped catalogue that does not load is `NotExamined::Catalogue`, not an error — the metadata pass still runs |

D158 (PNG at the same depth, palette → RGB only when needed and said;
lossless WebP → lossless WebP) and D159 (one pass, one writer; C2PA
dropped when pixels change) are confirmed as built.

## Deviations

| # | the plan | what was done | why |
|---|---|---|---|
| 1 | `decode(bytes) -> (Raster, Fidelity)` | `decode(bytes, container) -> Result<Result<Decoded, Skip>, PictureError>` | the container is already known from the metadata pass; an animation is a value, not an error |
| 2 | "samples outside the restored rectangles identical, through decoders the code under test does not use" | the suite decodes through `png`/`image-webp` directly — the same crates `decode` uses, but called by the test, not through `decode` | there is no third PNG or WebP decoder in the lock; the comparison does not go through the code under test |
| 3 | "the ICC profile byte-identical" | asserted for `iCCP` (PNG) and `ICCP` (WebP, in the reframe suite) and APP2 (JPEG, reframe suite) | — |
