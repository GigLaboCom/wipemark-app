## What was done

**`Restored` gains three fields**, appended after `exact`
(`crates/wipemark-pixels/src/restore.rs`):

| field | type | meaning |
|---|---|---|
| `consistency_px` | `f32` | the restored samples blended back, `α·L + (1 − α)·O` with the `α`, the logo and the gain 1 the restoration used, against the stored input **before** the restoration: the 95th percentile (nearest rank, as `texture`) of `|blend(O) − I|` over every sample with `NOISE_FLOOR ≤ α < opaque_above`, in 8-bit levels whatever the depth |
| `consistency_excluded` | `u32` | the samples left out because an error is expected there: every clamped sample, and the three colour samples of every hole |
| `consistency_dct` | `Option<f32>` | R8's; always `None` here, and then absent from the JSON (`skip_serializing_if`) |

**The measure is one function**, for the planar path to call too
(`crates/wipemark-pixels/src/verify.rs`, beside `percentile`):

```rust
pub(crate) fn consistency(
    pairs: impl IntoIterator<Item = (f64, f64)>, // (blended-back value, stored input value), 8-bit levels
    excluded: u32,                               // what the caller left out: clamped samples, hole samples
) -> Consistency                                 // Consistency { px: f32, excluded: u32 }
```

The RGB path (`restore_with`, the body `restore` had) collects the pairs as
it writes, in the same loop, from the very `o`, `v`, `a` and `logo[c]` it
uses; the planar path will hand Y samples at full resolution and chroma
samples with `ᾱ` to the same function, one percentile over both. The
written samples are what they were to the byte: `(o + 0.0).round()` is
`o.round()`, and on the fourteen fixtures every output's sha256 is the
base commit's (below).

**The hidden hook** for `a_restoration_off_by_one_level_is_seen`:
`#[doc(hidden)] pub fn restore_off_by(raster, verified, options, levels: f32)`
— `restore` with every restored sample moved by `levels` 8-bit levels after
the inverse, before it is written and measured. `restore` is
`restore_off_by(…, 0.0)` through one private `restore_with`; nothing else in
the product calls the hook.

**The capture noise a restoration takes off** (D246) is measured too: its
pixels are disjoint from the template's (`geometry::template_and_noise`
zeroes the template where the noise is), its `α` is in the counted range,
and it is restored with the same `L`. A noise sample whose inverse clamps
is excluded and counted in `consistency_excluded`, but **not** added to
`clamped`, which keeps its meaning and keeps `exact` where it was.

**The JSON** gains `"consistency_px"` and `"consistency_excluded"` after
`"exact"` in every `restored[]` entry, on every surface that writes
`PixelReport` (the CLI's `--json`, the MCP tools, the windows' Report copy).
`docs/architecture/visible-marks.md` ("The report") and
`docs/architecture/cli.md` (`--json`) say the fields and what they mean.
The CLI's and the windows' **words** do not change: a measure has no
sentence (D162's rule for a developer measure; nothing here asks for one).

**The tools.**

* `scripts/regress.py`: `consistency_px` is a measure under
  `TOLERANCE` `(0.2, 0.05)` `[tunable]` — the "not worse" rule of the

## Deviations from the document

1. **The 14-crop test is in `wipemark-picture`, not `wipemark-pixels/tests/exact.rs`.**
   `wipemark-pixels` has no codec, and its suites read "no photograph and no
   vendor file" (`tests/support/mod.rs`); the crops are JPEG and WebP too,
   and the user's path to them is `wipemark_picture::clean`. So
   `an_exact_inverse_is_consistent_to_rounding` is
   `crates/wipemark-picture/tests/consistency.rs` (a new file, so another
   branch's edits of `real.rs` cannot collide with it), and `exact.rs` carries the same
   identity on composites as `a_composited_mark_is_consistent_to_rounding`.
2. **`consistency_excluded` counts samples**: a hole is a pixel, so it is
   three samples. The test in the table, "`excluded == clamped`", holds
   where there are no holes; the general identity the tests hold is
   `excluded == clamped + 3·holes`.
3. **The capture noise taken off (D246) is measured**, and its clamps are
   excluded without entering `clamped` (above). The document does not
   mention that pass.
4. **`a_restoration_off_by_one_level_is_seen`** adds a 16-bit case and an
   upper bound (2.5), so the 8-bit scale is guarded.
5. **The third mutation** ("compute against `O_rec` instead of `I`") was
   made as the pair's reference side being `blend(O_rec)`: the measure then
   compares the restoration with itself and reads 0.
6. **Files touched beyond the list**: `recon_bench.rs` (it wrote `null`),
   `scripts/bench/README.md`, `apps/wipemark-cli/src/image.rs` (a unit test
   builds a `Restored` literal), `crates/wipemark-pixels/tests/verify.rs`
   (the JSON test), `lib.rs` (one `#[doc(hidden)] pub use`).
7. **`--new-fields`** was added (it did not exist), with two selftests.
8. **Two percentiles**: within a file `consistency_px` is the nearest-rank
   p95 over samples (the crate's `percentile`, as `texture`); across files
   `report.py` takes its own interpolated p95 (as it does for ΔE). Both are
   what their file already used.

## Questions

1. **A hole as three samples** in `consistency_excluded`, or as one pixel
   beside `holes`? Samples was chosen so that the field is one unit
   throughout; `holes` already counts the pixels.
2. **Clamps in the capture-noise pass** are excluded but not added to
   `clamped`, which would move `exact` (and so behaviour). Keep it so?
3. **The planar p95 "over both"**: at 4:2:0 Y has four samples for every
   chroma sample. One percentile over the pooled samples (what the
   function does when handed both) weighs Y four to one. Is that the
   intent, or should chroma be weighted by its footprint?
4. **`--new-fields` matches a field name anywhere** in the JSON tree, not at
   a path. For D305 the names are unique; a later decision with a common
   name (`kind`, `rect`) would want a path. Leave it until then?

## Decisions proposed

**D305**, as it should read in `docs/plan/README.md` §4:

> **D305** — `Restored` carries **`consistency_px`**: the restored samples
> blended back — `α·L + (1 − α)·O`, with the `α` (after any resampling), the
> logo and the gain 1 the restoration used — against the stored input
> before the restoration; the 95th percentile (nearest rank) of
> `|blend(O) − I|` over every restored sample with `NOISE_FLOOR ≤ α <
> opaque_above` (the capture noise a restoration takes off, D246,
> included), in 8-bit levels whatever the depth. **`consistency_excluded`**
> counts the samples left out because an error is expected there: every
> clamped sample, and the three colour samples of every hole.
> **`consistency_dct`**, the share of DCT coefficients outside their
> quantisation intervals, is set only by a path that chooses a value inside
> them (R8) and is absent from the JSON otherwise. The JSON gains the fields
> after `exact` (`visible-marks.md`, "The report"; `cli.md`, `--json`). A
> measure only: no bound, verdict, exit code or `*_left` flag reads it. On
> an exact inverse it is ≈ 0 by identity — at most half a level; 0.244–0.245
> on the 14 committed crops, PNG, JPEG and WebP — and the planar inverse
> (R6) computes it in the planes through the same function
> (`verify::consistency`, over pairs of a blended-back and a stored value).
> `regress.py` compares it under max(0.2 levels, 5 %) `[tunable]` and lets a
> run name the fields a decision adds (`--new-fields`); `report.py` shows its
> p95 per config and slice. (E12-R7, 2026-10-09; spec 06 §7, S4, D-new-1;
> it lands before R6, which uses it as its identity test.)
