## What was built

1. **The adapter** (`apps/wipemark-app/src/engine_host.rs`, H1–H5).
   `EngineHandle::complete` (busy per call) is gone; `for_job()` hands
   out a `JobEngine` that holds the busy count and the
   `JobStarted`/`JobEnded` pair for the **whole job**, takes `info()` once,
   delegates `complete`/`warmup`, and never unloads. Beside the slot the
   handle carries a `Pace` (executor + the last Check's rate), published by
   the host at every swap and whenever the backends land, the rate kept by
   `check_done`. `described()` says what is on duty without building or
   loading anything. `executor_of`: machine + GPU backend → `LocalGpu`,
   machine otherwise (unknown included) → `LocalCpu`, endpoint →
   `Endpoint`.
2. **The shared vocabulary** (`crates/wipemark-pipeline`): `asked`
   (`Asked`, `Asked::options`, `offered` — paraphrase/humanize/back_translate,
   `MOST` = 8, `fresh_seed` — 32 bits, std `RandomState`), `job::{wait,
   Ending, block_on}`, `cost::{Executor::as_str, Cost::to_value}`,
   `prompt::row::{PIVOT_KEY, pivot_of, overrides_from, lay_over, Laid,
   Override::by_hand}`.
3. **The MCP tool `rewrite`** (`apps/wipemark-app/src/mcp/{protocol,rewrite,server}.rs`).
   Arguments `text`, `tactic`, `intensity`, `candidates`, `rounds`,
   `format`, `aggressive`, `nfkc`, `seed`, `templates`, `dry_run`; answers
   `{"text","report"}` with `JobReport::to_json` verbatim in the text block
   and parsed as `structuredContent`; refuses every problem by name as an
   `isError` result; a call blocks until its job ends, a hang-up (peeked
   between events) or the 60-minute ceiling cancels it; `dry_run` prices
   with `described()` and loads nothing. The listing says the document goes
   wherever the Engine page sends it.
4. **The beacon** (`crates/wipemark-models/src/beacon.rs`,
   `Layout::beacon_path`): `<data dir>/mcp.json` = `{pid, port, address}`,
   written atomically by the supervisor on `Listening` (loopback or
   wildcard bind only, address always loopback), removed on stop, on a
   failed start and when the supervisor exits — only when the pid is ours.
5. **CLI `rewrite`** (`apps/wipemark-cli/src/{rewrite,app}.rs`). Flags as
   §4.6 of the document; `--engine`/`--model` removed. The application
   when its beacon passes the three checks, else the command's own local
   engine (`LocalEngine` under `local-llama`; `NotBuilt` without); exit
   codes 0/1/2/3 with 3 beating 1; `--json` = `{report, text|written,
   served_by}`; human report read off the JSON (the same form from both
   roads); price and progress on a terminal; Ctrl-C cancels (or hangs up
   on the application). `run::destination` was extracted from `clean` so
   both commands choose where a result goes by one function.
6. **`Unavailable::KeyUnsendable(KeyFault)`** — the transport refuses with
   it before a socket opens; four `engine-refusal-key-unsendable-*`
   sentences in en/ru/de, rendered by the app and the CLI.
7. **Core's dead report types removed**: `RewriteSummary`, `RiskLabel`,
   `FinalReport`; the baseline is `report::not_established::baseline()`.
8. **Words.** `settings-mcp-tools-layer-a` → `settings-mcp-tools` (three
   tools, and where a rewrite sends the document); `settings-engine-pending`,
   both check notes, `settings-models-pending`, `settings-mcp-description`
   and `setup-welcome-body` no longer say "nothing rewrites" — they say the
   windows do not, and an agent and the command line do. `cli-not-implemented`,
   `cli-arg-engine`, `cli-arg-model` deleted; `cli-arg-{intensity,format,
   prompts,seed}` and the `cli-rewrite-*`/`cli-prompts-*` family added, all
   three languages.
9. **Docs**: `docs/architecture/{cli,pipeline,local-engine,remote-engine}.md`.

## Deviations from the brief, and why

- **H16 — the CLI's own engine is the local model only.** The brief asks
  the CLI, with no application running, to use "the endpoint the rows
  describe (key from the credential store, `engine::refusal` rules
  unchanged)". `engine::refusal`, `duty::on_duty`, the profiles and
  `engine::account_of` live in `apps/wipemark-app`, which no other crate
  may depend on; carrying them over would be a second copy of the
  default-deny rule — the one rule CLAUDE.md says protects a document — and
  moving them into a library is a refactor of ~3 000 lines entangled with
  `gpui::SharedString` and the catalogue. So the CLI reads `engine.serves`
  and `engine.provider` and refuses, naming the application, whenever the
  answer would be an endpoint; it loads the local model otherwise. The
  refusal is honest and exits 2; nothing is sent anywhere by a rule
  restated here. If the owner wants the endpoint from the CLI with the
  application closed, the step is "move the endpoint vocabulary into a
  library crate", its own document.
- **The MCP tool gained `templates`** (not in the brief's list): `--prompts`
  must hold on both roads, and the application's road has no other way to
  carry a template. The tool and the CLI validate with the one
  `prompt::row::lay_over`.
- **`EngineHandle::complete` was removed**, not kept beside `for_job`: a
  per-call road through the handle is exactly the hole H1 closes, and
  nothing else called it.
- **Rows in the database that do not validate are not refused**, only the
  caller's own templates are (`lay_over`): a row this build cannot use is
  the shipped template (the repository's row rule); a template handed in for
  this run is a request by name.
- **The result infix stays `.cleaned`** for a rewrite (`name.cleaned.ext`),
  as the queue's `Destination::beside` already does — one result-naming
  rule, Retention's.
- **No queue.** The MCP tool and the CLI call `start` directly (E4-4's
  "or bypass the queue"): an agent's call waits for its own answer, and
  the queue would serialise it behind a batch.

## Open questions for the owner

1. **The command line with the application closed and an endpoint
   chosen** now refuses and says to start the application. Should the
   command line be able to send a document to an endpoint on its own? It
   means moving the endpoint rules out of the application first (a step of
   its own) — and a second program on this machine that sends documents
   to a server.
2. **How long may an agent's rewrite take** before it is stopped? It is an
   hour now. A long document on a laptop without a graphics card can need
   more.
3. **Should an agent be allowed the "structural" tactic** (rewrite from an
   outline)? It is refused now, because in the application it sits behind a
   confirmation and an agent's request is not one.
