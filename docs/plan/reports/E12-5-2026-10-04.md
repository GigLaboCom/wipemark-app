## What was built

* **CLI** (`apps/wipemark-cli/src/image.rs`): `inspect` and `clean` on a
  picture go through `wipemark_picture`; a "Visible marks" section (each
  finding with profile, vendor and product as identifiers, its rectangle,
  row or search, and "proved" with correlation, strength and edge ratio or
  "seen, not proved" with the reason and its number; what was restored,
  exact or not, holes; or why the pixels were not examined); how the
  picture was written back; "is still in the result" when a mark is left;
  the picture's third shelf (`report::picture_shelf`). Exits:
  `picture_inspect_exit` (3 not examined › 1 mark or provenance › 0) and
  `clean_exit` over `strip_exit` (3 for provenance left — not written —, a
  mark left or pixels not examined — written —; 1 when a mark was restored
  or provenance removed; else 0). `refuse_picture` for a restored picture
  that could not be written back or failed its own check (3, nothing
  written). The module's exit table rewritten.
* **`audit`** (`audit.rs`): `Status::Image(PictureInspection)`; a visible
  mark is a finding (`cli-audit-image-visible`); an unexamined picture is a
  hole (listed under unreadable, a SARIF notification); SARIF
  `visible-<profile>` rules and results, `level` error/warning by verdict,
  no region, `properties.rect`/`verdict`/`ncc`; `run.properties.not_established`
  leads with `invisible-pixel-marks` when a picture was scanned.
* **MCP** (`apps/wipemark-app/src/mcp/image.rs`): both tools through
  `wipemark_picture`; `Refusal::Encode` and `Refusal::Proof`; a mark left is
  in the report, the image comes back. The banner `settings-mcp-tools`
  reworded in en/ru/de.
* **`wipemark-picture`**: `NotExamined::Decode` (pixels that do not decode
  are a value, the metadata pass still runs); `inspect` returns
  `ImageError` only; `inconclusive()`; the JSON flattened so E11's keys stay
  where they were.
* **Catalogue** (en/ru/de): 28 `cli-image-visible-*`/`-refusal-*`/
  `-encoded-*`/`-proof-failed`/`-encode-failed` keys, `cli-audit-image-visible`,
  `report-not-established-invisible-pixel-marks`, `cli-image-pixels`
  reworded (the pixels *are* examined now — for visible marks).
* **i18n gates**: `the_picture_shelf_is_never_empty_in_any_language` and
  `no_catalogue_string_names_a_mark_vendor` (Q-V9), with `wipemark-pixels`
  as a dev-dependency of `wipemark-i18n` (the dependency script says so).
* **Tests**: CLI unit `a_visible_mark_left_behind_never_exits_0`; CLI
  binary `tests/visible.rs` (4); `tests/image.rs` and the MCP protocol test
  updated to the picture's shelf and the pass.
* `docs/plan/reports/E11-2-mutate.py`: M13 re-pointed (a picture's finding
  is metadata or a visible mark), M16 narrowed to the library's own test
  (the surfaces now write the picture's shelf from `wipemark-pixels`).

## Decisions (I-numbers; mapped from D188 by the series report)

| I | decision |
|---|---|
| I32 | **No flag** (Q-V1): `--keep-visible` is not built; D160 amended |
| I33 | **A mark left writes the result and exits 3** — not a refusal; the report says what is left. A result that still carries provenance *metadata* stays a refusal with nothing written (E11-2's D132) |
| I34 | **Not examined is 3 when the pass should have run** (a catalogue that did not load, pixels that do not decode); an animation is said and does not change the exit — the pass does not apply to one |
| I35 | **JSON stays E11's at the top level** and grows `visible`, `encoding`, `marks_left`; `not_established` becomes the picture's shelf (four ids) |
| I36 | **MCP returns the image when a mark is left**, with `marks_left: true` — a refusal there would throw away the metadata pass that did succeed |
| I37 | **SARIF: `visible-<profile>` rules**, error when proved and warning when not, the rectangle in `properties` |
| I38 | **`wipemark-pixels` is a dev-dependency of `wipemark-i18n`** for the shelf and vendor gates, as core is |

## Deviations

| # | the plan | what was done | why |
|---|---|---|---|
| 1 | `clean` restores by default and `--keep-visible` opts out | no flag at all | the owner's answer to Q-V1 |
| 2 | `--json` "carries the `visible` array" | `visible` is an object (`examined`, `restorable`, `found`, `restored`, or `why`) | a pass that did not run needs a reason, not an empty array |
| 3 | end-to-end MCP test on a marked picture | the protocol suite asserts the pass ran on every answer; the marked case is covered by the CLI's binary suite and `wipemark-picture`'s | the MCP suite has no generator for a marked picture and its 1 MiB limit is the same code path |
