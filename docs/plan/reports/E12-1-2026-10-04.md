**What this agent could and could not do.** The owner's rule for this run:
*write the code, do not run it — compiling Rust is the most the container
does.* Every gate that compiles was run (below); **no test was executed**,
so no threshold was measured here and no timing was taken. And one more
limit, met during the step: **cloning GeminiWatermarkTool was refused** by
the container's policy (external code). Everything that needs GWT's files
is therefore built so that the host finishes it with one script — see
"Owed to the host".

* `ncc.rs` — `TM_CCOEFF_NORMED` with `f64` integral images and a flatness

* `propose.rs` — rows with whole- then quarter-pixel refinement; the

* `verify.rs` — edge energy, the unclamped gain sweep, the three limits,

* `restore.rs` — the inverse (GWT provenance header), holes, clamps,

* `lib.rs` — `examine`, `restore`, `clean` (with the second pass), the
  choice among overlapping findings, `PixelReport::to_json`,
  `not_established` (`invisible-pixel-marks` first, then core's three),

* `NOTICE` — the GWT section with the copyright line and the full MIT text;
  `marks/README.md`; `marks/gwt/extract.py`; `docs/architecture/visible-marks.md`;

## Decisions (I-numbers; mapped from D170 by the series report)

| I | decision |
|---|---|
| I6 | **A map at a sub-pixel place and size is an exact area integral** of the map read as constant per sample, not 4×4 bilinear supersampling (the plan's wording). The native-size identity holds by construction, the mass of the map is conserved at every scale (`a_resampled_shape_keeps_the_maps_mass`), and the mutation "pixel corners instead of centres" becomes "the footprint shifted by half a pixel" |
| I7 | **The plan's `restore(…) -> Restored` returns `Result<Restored, RestoreError>`**: a `Verified` from a raster of another size is `Elsewhere`, never a write out of bounds |
| I8 | **`Refusal::Opaque { holes }` only when every pixel of the mark is a hole**; a mark with some holes verifies on the rest (the plan) and its restoration is not exact |
| I9 | **Contour pixels beside a hole are not measured**: the inverse is not defined there, and the edge between a hole and its restored ring would refuse every opaque-cored mark |
| I10 | **A flat window scores 0**: variance below 10⁻¹⁰ per pixel is rounding, and dividing by it made a flat corner a perfect match |
| I11 | **The search is proposed only when no row reaches `min_ncc`** (per profile), as the plan says; rows are all tried |
| I12 | **The choice among overlapping findings sorts** verified → lower ratio → (within 0.01) row before search → higher NCC; losers become `also_tried` |
| I13 | **`logo_map` is refused** ("not in this version"): no restoration path for a per-pixel colour yet; the schema keeps the key |
| I14 | **All four layouts work** (the plan asked for two; the code is identical, the type was ready) |
| I15 | **V2's small rows are not in the manifest** (see below): until the formula is ported, a V2 picture under 1025×1025 is found by the search and is never exact |

D150–D157 and D163–D165 are confirmed as written, with these amendments:
D153's 4×4 supersampling → I6; D154's numbers are the starting values,
unmeasured here; D163's "the placement numbers become rows" — V1's and V2's
large row are in; V2's small rows are owed.
