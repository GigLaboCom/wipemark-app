# Localization — Fluent, negotiation, and the gates

Epic **E6**. Every string a person reads comes out of a message
catalogue; nothing a machine reads does. This document is the shape of
that, the decisions that look like extra work, and what to do when you
add a language or a string.

## The shape

```
crates/wipemark-i18n/
  i18n/en-US/wipemark.ftl   the source of truth — build.rs reads this one
  i18n/de/wipemark.ftl      translations. Same keys, no more, no fewer
  i18n/ru/wipemark.ftl
  build.rs                  parses every catalogue, generates `Message`
  src/catalogue.rs          rust-embed + bundle construction
  src/preference.rs         LanguagePreference, and the precedence chain
  src/lib.rs                Localizer, the chain, t() / t_args()
  src/tests.rs              the gates
apps/wipemark-app/src/language.rs   the selector: rows, labels, clicks
```

`build.rs` walks `i18n/en-US/wipemark.ftl` and writes
`$OUT_DIR/messages.rs` with a `Message` enum, `Message::ALL`,
`Message::id()` and `Message::variables()`. `src/lib.rs` `include!`s it.
Adding a string is therefore: add it to the English catalogue, rebuild,
translate. There is no enum to extend and no match arm to keep in sync —
the same reasoning, and the same `build.rs` idiom, as `wipemark-core`'s
UCD tables and the app's `IconName`.

## Using one

```rust
use wipemark_i18n::{args, t, t_args, Message};

t(Message::PaneDocumentsTitle)
t_args(Message::LanguageSystem, &args!("language" => "Deutsch"))
```

A key that is not in the catalogue does not compile. A key that is in
the catalogue and in no translation renders in English. A key that no
catalogue in the chain has renders as its own id — visible, and named.

## Why this stack

**Project Fluent** rather than a key–value table. The first language
whose plurals are not English's ends the table: Russian selects between
*one*, *few*, *many* and *other* on the value of the number, and the
boundaries are not `== 1`. Fluent puts that decision in the catalogue,
where the person who speaks the language can make it, instead of in a
`format!` at a call site that does not know what language it is in.
`plural_categories_come_from_the_language_not_the_call_site` is the
proof, over a fixture rather than a shipped string.

**`fluent-langneg` 0.13** rather than a `HashMap` lookup, and 0.13
rather than 0.14: 0.14 moved to `icu_locid` for its tag type while
`fluent-bundle` 0.16 still speaks `unic-langid`, and mixing the two
means converting every tag through a string. 0.13 is the pair
`i18n-embed` ships.

**Typed keys from `build.rs`** rather than `i18n-embed-fl`'s `fl!`. The
macro checks a key against the fallback catalogue at compile time, which
is the property worth having, but it resolves its config relative to the
crate being compiled — so a shared catalogue behind two binaries means
either a config file per binary or a catalogue per binary. Generating
the enum gets the same compile-time check, works across crates, and adds
one thing the macro cannot: `Message::ALL` is iterable, so the suite
proves that *every* message renders in *every* language rather than
spot-checking the ones somebody remembered.

## Which strings are localized

Everything a person reads. Nothing a machine reads.

Catalogue ids, `--json` field names, config keys, `wipemark_core::Vendor`
names and the canonical English in `wipemark_core::report::not_established`
are **formats**, not prose: translating one strands the file or the
pipeline that contains it. `vendor.rs` has said "never localise this"
since E0 and still means it.

The layering follows from that, and `check-dep-direction.sh` enforces
it: **no library may depend on `wipemark-i18n`.** A `wipemark-engine`
that formatted its own error messages would be unusable from a CLI that
had chosen a different language, and untestable without deciding which
one. Libraries hand up structured values; the surface renders them,
because the surface is also the only thing that knows whether it is
drawing a window or writing to a pipe.

### Character names: the one exception that reads like prose

`ZERO WIDTH SPACE` is what `wipemark_core::name_of` returns for U+200B:
the character's `Name` property in the Unicode Character Database. It
reads like English and it is not prose — it is an identifier of the
standard, like the code point itself and like `Vendor::as_str()`. So it
is printed beside its `U+XXXX` (in monospace where a window has
monospace), **never translated and never put in the catalogue**: a
translated name is one no reference, search engine or other tool knows.
Code points that have no name use the UCD's code point labels
(`<private-use-E000>`, `<noncharacter-FDD0>`, `<reserved-E0080>`), which
are formats too.

What is localized is everything around it: the class
(`unicode-class-<id>`, "zero-width character") and the confidence
(`confidence-<id>`, "confirmed"), keyed by the stable ids
`UnicodeClass::as_str` and `Confidence::as_str`. A row of the CLI's
human report reads `U+200B ZERO WIDTH SPACE · zero-width character ·
confirmed · …` in every language, and only the last three parts change.
`--json` and the MCP server carry the name as `name` and never a class
label — a machine reads those, and nothing a machine reads is
translated.

Basis: the E1 spec's A §5.5, owner question Q-A6 and plan decision D16.
If the owner vetoes it, windows show only `U+XXXX` and the class, and
`name_of` stays for `--json` and MCP.

## `Rendering`: the one that is not cosmetic

Fluent wraps interpolated values in U+2068 and U+2069 so that
`Files: { $name }` reads correctly when `$name` is Arabic and the
sentence around it is not. Those two code points are
`UnicodeClass::BidiControl` — exactly what Layer A removes.

So `wipemark-app` renders as `Rendering::Ui` and `wipemark-cli` as
`Rendering::PlainText`, and `PlainText` is the default, because the
failure mode of the wrong choice is invisible in one direction and
merely imperfect in the other. A CLI that printed isolates into a file
would be marking the documents it was pointed at, and a `--json` report
carrying them would fail this product's own inspection.

Two tests hold it: `no_message_carries_a_character_layer_a_would_strip`
over every message in every language, and
`help_carries_no_character_layer_a_would_strip` over the rendered
`--help` of every command. A third,
`a_window_isolates_what_a_pipe_must_not`, checks that the two renderings
are actually different — otherwise the first two would pass for the
wrong reason.

**A window's text that the window does not draw** is the exception
inside `Ui`: a window title goes to the platform — the window list, the
taskbar, X11's `_NET_WM_NAME`, a screen reader — and there the isolates
are two invisible characters, not layout hints. So a `Ui` localizer has a
per-call road to plain text, `Localizer::format_plain` /
`format_args_plain` (a second, isolate-free copy of the chain, built the
first time it is asked), with the globals `t_plain` / `t_args_plain` and
`with_localizer` for a builder that wants a localizer handed in. The
application builds every title through `apps/wipemark-app/src/title.rs`
(`Title::text`) and nowhere else; `no_window_title_carries_an_invisible_character`
walks every title in every language under `Ui`, with Latin, Arabic,
Hebrew and Cyrillic file names (tails-1; before it, the Compare window's
title carried U+2068/U+2069 around the file name). The tray's tooltip is
the literal brand name and its items interpolate nothing, so they need
neither.

## Choosing a language

```
--language de          (CLI only)
WIPEMARK_LANG=de
ui.language = "de"     in wipemark.db
the desktop            LANG/LC_ALL on unix, preferred languages elsewhere
```

In that order, each level skipped when it is not a language tag at all,
so a typo in one place cannot hide the next. `system` (or `auto`) is the
default and means the last line.

Negotiation is BCP-47 extended filtering, so `de-AT` gets the `de`
catalogue and `pt-BR` does not get `pt-PT` by accident. What comes back
is an ordered **chain**, not one answer, and every catalogue in it is
loaded: a language whose translation is 80% done shows 80% of the window
in that language and the rest in English. Translations are always
allowed to lag — `shipped_languages_are_complete` is what says the ones
in *this* repo do not.

`--language pt-BR` warns, because the user asked out loud and did not
get it. A *config* naming `pt-BR` does not warn and is not rewritten:
the window runs on whatever negotiation resolved to, the file still says
what the user wanted, and a `pt-BR` catalogue shipping later makes it
come true without them choosing again.

### One honest difference from the theme

`ThemePreference::System` is a live promise: GPUI hands the window an
appearance change and the observer re-applies it. There is no equivalent
notification for the OS *language*, so `LanguagePreference::System`
resolves once, at startup, and a language changed on the desktop reaches
Wipemark at its next launch. Nothing in the UI claims otherwise.

## Adding a language

1. `mkdir crates/wipemark-i18n/i18n/<tag>` — the directory name is the
   BCP-47 tag, canonically spelled, because it is what negotiation
   matches on and what `bundle` looks up.
2. Copy `en-US/wipemark.ftl` into it and translate. Keep every key, keep
   every `{ $variable }`, and set `language-autonym` to what the
   language calls itself.
3. Rebuild. The selector, the negotiator and the tests all read the same
   embedded set, so there is no list to register it in.

`cargo test -p wipemark-i18n` then tells you what is missing, what is
spare, which variable was renamed, and whether any of it promises more
than the product does.

## Adding a string

1. Add the key to `i18n/en-US/wipemark.ftl`. Put a `#` comment above it
   if a translator would need one — it becomes the rustdoc on the
   generated variant.
2. Use `Message::TheNewKey`.
3. Translate it in the other catalogues, or watch
   `shipped_languages_are_complete` tell you which ones you skipped.

## The gates

`cargo test -p wipemark-i18n`, and every one of them can fail — checked
by deleting the protection and watching the suite go red:

| gate | what it catches |
|---|---|
| `every_message_renders_in_every_language` | a message that renders as its own key |
| `shipped_languages_are_complete` | a translation that shipped half-done |
| `no_language_defines_a_message_nobody_asks_for` | a translator's typo'd key, which looks exactly like "not translated yet" |
| `variables_match_the_fallback` | a renamed `$variable` — renders perfectly, drops the value |
| `the_third_shelf_is_never_empty_in_any_language` | a claim on the honesty contract with no translation |
| `no_language_promises_more_than_the_product_does` | "undetectable", in any of the three languages |
| `no_message_carries_a_character_layer_a_would_strip` | Wipemark's own strings failing Wipemark's own inspection |
| `a_window_isolates_what_a_pipe_must_not` | `Rendering` having become a no-op |
| `a_window_can_ask_for_plain_text_per_call` | the per-call plain road reading the isolating chain |
| `the_embedded_catalogues_are_the_ones_that_were_built` | a language `build.rs` saw and rust-embed did not |
| `the_theme_labels_are_distinct_in_every_language` | two buttons reading the same word |
| `every_unicode_class_and_confidence_reads_in_every_language` | a Layer A class or confidence with no words for it in some language — a report row that prints a key, or English inside a German report |

Plus `every_argument_and_subcommand_has_help` in `wipemark-cli`, which
is what replaced the doc comments clap used to take its help from: an
argument added with no catalogue entry now has *no* help, rather than a
doc comment quietly standing in for one. And
`the_human_report_carries_no_character_layer_a_would_strip`, also in
`wipemark-cli`, which renders the `inspect` and `clean` reports in every
shipped language — 1234 findings in one row, so a digit-grouping number
formatter would be caught too — and fails on any character Layer A
would remove, Fluent's isolates first among them.

## clap has no localization

`Usage:`, `Commands:`, `Options:`, `Arguments:`, `-h`'s and `-V`'s help
and the `help` subcommand's description are English constants inside
clap. All of them are reachable, none of them the same way:

* headings — only by not using the `{all-args}` placeholder that draws
  them. `help_template` lays the sections out by hand instead, built per
  command so a leaf never prints an empty `Commands:`.
* `-h`, `-V`, `help` — through `mut_arg`/`mut_subcommand`, but they do
  not *exist* until `Command::build` has run, and asking earlier panics
  with ``Command `help` is undefined``. Hence two passes in
  `localized_command`, the second walking the built tree.

Everything else — the derive's own structure, flags, defaults, arities —
stays in the derive where `debug_assert` can check it.
