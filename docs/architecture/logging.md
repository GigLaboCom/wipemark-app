# Logging

Ported from `heretic-lazy-shot`. Same three guarantees, different
plumbing:

1. A **rotating file on disk**, because a bundled `.app` has no terminal
   and a CI runner keeps no scrollback.
2. A **stderr mirror**, on for a development build of the app and off
   for the CLI.
3. A **panic hook that reaches the file first**, because the crash worth
   having a log for is the one that never unwinds.

Everything lives in `crates/wipemark-log`. Applications call
`wipemark_log::init` as the first statement in `main`; nothing else in
the tree installs a subscriber.

## Where

```text
<data dir>/logs/wipemark_2026-09-08_09-14-02.log       the window
<data dir>/logs/wipemark-cli_2026-09-08_09-15-40.log   the CLI
```

`<data dir>` is `Layout::root()` — so `WIPEMARK_DATA_DIR` moves the logs
with everything else, and a scratch run cannot write to the real
directory. On macOS that is
`~/Library/Application Support/com.GigLabo.wipemark/logs`.

The two binaries share a directory and are told apart by the file name
stem. Pruning is per-stem: the app rotating never deletes the CLI's
history.

## Rotation

| Limit | Value | Why |
| --- | --- | --- |
| size | 10 MB | same as lazy-shot |
| age | 24 h | same as lazy-shot |
| files kept | 10 | **the one deliberate deviation** |

lazy-shot keeps every file it has ever written. A pre-commit hook that
runs `wipemark-cli` fifty times a day would grow a directory nobody ever
opens, so a rotation prunes all but the newest ten of its own stem.
Files that are not ours — including the other binary's — are never
touched.

## Levels

`WIPEMARK_LOG`, then `RUST_LOG`, then `wipemark_log::default_filter()`.
Both variables take the full `EnvFilter` syntax:

```sh
WIPEMARK_LOG=info,wipemark_core=trace cargo run -p wipemark-app
```

The product's own variable is checked first so that turning Wipemark up
does not also turn up every other Rust tool in the shell.

The default is **`info` for the world, `debug` for our own crates** in a
debug build, and `info` everywhere in a release one. The scoping is not
tidiness: `gpui` and its dependencies log through the `log` crate,
`tracing-log` bridges those records in, and a flat `debug` buries every
line this product wrote under a renderer talking about frames.

The list of "our own crates" is generated by `crates/wipemark-log/build.rs`
from `[workspace] members`, for the same reason the i18n `Message` enum
is generated from the catalogue: a hand-kept list drifts, and a new
crate whose `debug!` calls silently vanished would give nobody a reason
to suspect this file.

## Writes are unbuffered, on purpose

Every event goes straight to `File::write_all`. A `BufWriter` would be
faster and would also lose the last few kilobytes on `abort()` — which
is precisely the moment the log earns its keep. Events are one short
line; the cost is a syscall, not a seek.

The lock is held for the *whole* event rather than per `write` call, so
two threads never produce one interleaved line.

Errors are swallowed. A full disk is not a reason to take the window
down, and `tracing` has nowhere to report one anyway: the writer it is
calling *is* the reporting channel. An unopenable directory produces one
line on stderr and then silence.

## The one rule this bends, and why

`CLAUDE.md` says nothing blocks the GPUI thread. A log write *is* on the
calling thread, GPUI's included.

That is a considered trade and not an oversight. The two requirements
are in direct tension: a background writer keeps the foreground thread
free but loses its queue on `abort()`, which is the one crash this whole
file exists to capture. Making the writer asynchronous would buy a
theoretical stall back and give up the guarantee.

The write is one `write(2)` of a couple of hundred bytes to an already
open descriptor — microseconds, and no allocation of a 2 GB model in
sight. It is not free on a network home directory, which is exactly the
caveat `config.toml` carries, so:

* **Do not log per frame, per keystroke or per character.** Log per
  operation, per stage and per outcome.
* If a hot path ever needs tracing, put it behind `trace!` and leave the
  default filter to switch it off.

If a stall ever shows up in a profile, the fix is `tracing-appender`'s
non-blocking writer for the `info` layer with the panic hook kept on a
synchronous one — not one writer trying to be both.

## The panic hook

Rust runs the panic hook *before* unwinding begins, so a panic that ends
in `abort()` has already passed through it. That case is not
hypothetical here: GPUI calls our code from AppKit callbacks, and a
panic crossing that `extern "C"` boundary becomes `panic_cannot_unwind`
→ `abort()`. The default hook writes to stderr, and stderr is gone on
`abort()` — and gone anyway in a bundled `.app`. So the single most
likely crash this product has is the one that would otherwise leave no
trace at all.

The hook logs message, location, thread and a `force_capture()`
backtrace through `tracing::error!`, then chains to the previous hook so
`cargo run` output is unchanged. `force_capture` and not `capture`:
without `RUST_BACKTRACE` the latter returns `Disabled`, and a released
build is exactly where nobody thought to set it.

```sh
RUST_BACKTRACE=full cargo run -p wipemark-app
# then: grep -l 'PANIC' ~/Library/Application\ Support/com.GigLabo.wipemark/logs/*
```

## Rules

* **Libraries never install a subscriber.** They emit through the
  `tracing` macros and say nothing about where the output lands. A
  library that chose the format would choose it for every binary that
  ever linked it — the same reason `wipemark-i18n` is off limits below
  the applications, and `check-dep-direction.sh` enforces both.

* **Log lines are never localized.** They are read by whoever is
  debugging, not by whoever ran the program. Catalogue strings are for
  the window and the terminal; the file gets English. This is the same
  boundary as `--json` field names and config keys: *every string a
  person reads comes from the catalogue; nothing a machine reads does*.

* **The document never reaches a log line.** Spec §6.3 keeps text out of
  `history.jsonl`, and a log file carrying the paragraph a user was
  scrubbing is the same leak through a different door — worse, because
  it outlives the session on disk. Log *shapes*: lengths, offsets, code
  points, counts, outcomes. `wipemark_log::Elided` is for the cases
  where a string was about to be interpolated by reflex:

  ```rust
  tracing::debug!(source = %Elided::from(text), "scrubbing");
  // source=<elided chars=812 bytes=847>
  ```

* **Structure goes in fields, not in the message.** `tracing`'s fields
  are what makes a filter and a future JSON layer possible.

  ```rust
  tracing::info!(stage = %stage, removed = count, "layer A complete");   // yes
  tracing::info!("layer A complete: {stage}, removed {count}");          // no
  ```

* **The CLI's stderr mirror stays off unless asked.** That stream is a
  contract: a pre-commit hook shows it to its user and `--json` sits on
  stdout beside it. INFO lines poured into either land inside somebody's
  parser. `WIPEMARK_LOG` turns the mirror on, which is what asking for
  logs on a terminal means.

* **The subscriber goes up before the config comes in.** A config file
  this build cannot parse is a warning, and a warning emitted before the
  subscriber exists is a warning nobody ever sees.

## What the port changed

| lazy-shot | Wipemark | Why |
| --- | --- | --- |
| hand-written `log::Log` | `tracing` `MakeWriter` + layer | the workspace already speaks `tracing`; `wipemark-i18n` emits through it |
| stderr mirror by byte copy inside the writer | a second `fmt` layer | the file gets no ANSI escapes, the terminal keeps its colours |
| `Trace` / `Info` from `cfg!(debug_assertions)` | `EnvFilter`, scoped to our crates | a flat level cannot work here: `gpui` logs through the bridged `log` crate |
| every file kept forever | newest 10 per stem | a hook that runs all day |
| `get_log_dir` Tauri command | `Logging::directory()` / `current_file()` | E6 / S6.1 hangs "reveal logs" off it |
| `[MCP] EVENT key=value` helpers | `target:` + `tracing` fields | same idea, no string building |
